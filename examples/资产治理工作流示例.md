#资产治理工作流示例

这份示例说明如何使用 `assets` 与 `scripts/asset-tools` 跑通一条最小资产治理流程。

## 示例目标
以 `example-card`组件为例，演示：

1. 创建 manifest
2. 校验依赖兼容性
3.评估后晋升状态
4.具备条件后再允许同步

---

## 已提供的示例文件
- `assets/components/candidates/example-card.vue`
- `assets/components/manifests/example-card.manifest.json`

该示例当前状态：
- `status = candidate`
- `maturityLevel = L1`
-依赖仅使用 `vue` 与 `element-plus`

---

## 示例命令

###1.生成一个新的页面 manifest
```powershell
node E:/work/ai-web-system/scripts/asset-tools/create-manifest.mjs --type=page --name=demo-detail-page
```

###2. 检查示例组件兼容性
```powershell
node E:/work/ai-web-system/scripts/asset-tools/validate-asset-compatibility.mjs --manifest=assets/components/manifests/example-card.manifest.json
```

###3. 将示例组件从 candidate 晋升为 official
```powershell
node E:/work/ai-web-system/scripts/asset-tools/promote-asset.mjs --manifest=assets/components/manifests/example-card.manifest.json --status=official --maturityLevel=L2
```

###4. 如果后续允许同步，再执行同步脚本
在 manifest 中将 `sync.allowed` 改为 `true` 后，再执行：

```powershell
node E:/work/ai-web-system/scripts/asset-tools/sync-asset-to-project.mjs --source=assets/components/candidates/example-card.vue --manifest=assets/components/manifests/example-card.manifest.json --target=packages/ui/src/components/example-card.vue
```

###5. 汇总当前所有 manifest 的回写项
```powershell
node E:/work/ai-web-system/scripts/asset-tools/collect-writeback-items.mjs --dir=assets
```

---

## 推荐真实使用顺序
1. AI先生成组件或页面草稿到 `assets/components/candidates` 或 `assets/pages/drafts`
2.立即创建对应 manifest
3. 跑依赖兼容性校验
4. 用评审规范决定是否晋升到 `official`
5.只有在 `sync.allowed = true` 时，才允许同步到 `project-mamba`

---

##这份示例的意义
它的目标不是证明脚本已经最终完备，而是让你的体系从：

-只有文档

变成：

- 有目录
- 有模板
- 有脚本
- 有示例
- 有可直接运行的演示组件

这样你后续再补 Agent 或进一步脚本化时，就不再是纯概念设计，而是基于一套已经可演示、可扩展的资产治理骨架继续迭代。
