# 四层关系

## 目标

说明 `ai-web-system` 最核心的四层结构，以及它们之间的依赖关系。

## 四层结构

1. 标准层
2. 规则编排层
3. 协议层
4. 执行与治理层

这四层不是并列堆放，而是上下协作：

- 标准层定义规则
- 规则编排层把约束挂到具体工具
- 协议层组织任务执行与分工
- 执行与治理层负责校验、同步、回写和落地

## 第一层：标准层

回答的是：什么叫做对，什么叫做稳定。

主要目录：

- `standards/`
- `docs/`

## 第二层：规则编排层

回答的是：哪些约束应该在当前 AI 环境中默认生效。

主要目录：

- `rules/`
- `.cursor/`
- `.trae/`

## 第三层：协议层

回答的是：任务怎么触发、怎么执行、由谁承接。

主要目录：

- `skills/`
- `agents/`

这里已经不再单独维护 `commands/` 层；显式调用直接落到对应 skill。

## 第四层：执行与治理层

回答的是：怎么把前面三层跑通，并保证结果可控。

主要目录：

- `scripts/`
- `examples/`
- `docs/` 中的治理文档

## 四层之间的关系

### 标准层 -> 规则编排层

规则编排层必须引用标准层，否则环境约束会越来越像临时习惯。

### 标准层 -> 协议层

协议层必须建立在标准之上，否则不同 skill 会输出彼此冲突的做法。

### 协议层 -> 执行与治理层

脚本、示例和治理流程要知道协议层怎样组织任务，才能真正承接执行。

### 执行与治理层 -> 标准层 / 文档层

执行过程中发现的新规律，必须能回写到标准、文档或示例里，否则系统只会消耗知识，不会积累知识。
