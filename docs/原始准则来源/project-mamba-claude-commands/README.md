# project-mamba .claude commands 原始档案

这里完整保存 `E:\work\project-mamba\.claude\commands` 的原始 md 文件。

## 放在这里的目的
1. 保留你原始方法论和角色设定的出处
2. 方便回看某条规则最初是怎么表达的
3. 作为标准库抽取时的证据来源之一
4. 避免标准本体重构后丢失原始上下文

## 为什么不放进 standards
因为这些文件里混合了三种内容：
- 长期规则
- 工作流步骤
- 角色提示词

其中只有“长期规则”应该进入标准本体。
其余内容不应直接进入标准库正式条目。

## 和标准本体的关系
- 原始 md：来源档案
- `standards`：整理后的标准本体
- `skills`：未来面向不同 AI 工具的工作流入口模板
- `06-治理机制`：说明规则如何入库、谁来维护、依据是什么

## 关于你原始 md 里的“角色设定”
例如：
- 你是一名资深交互视觉设计师
- 你是一名资深前端开发工程师

这些角色设定，本质上属于“执行角色 / 提示词角色”。
它们回答的是：
- 模型以什么身份工作
- 处理任务时优先关注什么
- 输出时采用什么角度

而 `standards/06-治理机制/角色与职责.md` 里的角色与职责，属于“治理角色”。
它回答的是：
- 谁负责维护标准
- 谁负责提炼规则
- 谁负责审查候选规则
- 谁负责执行和使用标准

两者不是冲突关系，而是不同层级：
- 原始 md 里的角色 = 执行层 / prompt 层角色
- 治理机制里的角色 = 标准库治理层角色

## 以后怎么用
- 当你要追溯某条规则最初来源时，看这里
- 当你要维护正式规则时，改 `standards`
- 当你要做通用入口模板时，改 `skills`
