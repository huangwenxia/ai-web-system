# 页面分析

对当前页面或截图，同时从 UX 和 UI 两个维度做全面诊断，找出问题并给出优化方案。

---

| -------------- | ------------------------------------------------------------------- | ------------------------- |

## 工作流程

```
需求文档 → prototype.md（业务逻辑和交互设计）→ 页面设计.md（视觉设计）→ frontend.md（前端开发）
 ↓ ui.md（UI 准则库）
 ↓ 页面分析.md（UX/UI 分析，可并行）
```

本技能在工作流程中的位置：作为 `ux.md` 和 `ui.md` 的组合快捷方式，适合同时需要 UX 和 UI 分析的场景。如果只需要 UX 分析，请使用 `/ux`；如果只需要 UI 分析，请使用 `/ui`。

## 分析维度

### UX（用户体验）

1. **信息层级** — 用户第一眼看到什么？重要信息是否突出？
2. **操作路径** — 核心操作是否易达？几步能完成目标？
3. **反馈机制** — 操作后有没有状态变化告知用户？
4. **认知负担** — 有没有让用户"想太多"的地方？选项过多、标签模糊、流程不清？
5. **一致性** — 同类操作入口是否统一？相同数据是否用相同方式呈现？
6. **边界状态** — 空态、加载、错误有没有处理？

### UI（视觉设计）

1. **视觉层级** — 主次关系是否清晰？字号、字重、颜色是否体现优先级？
2. **间距与对齐** — 元素间距是否一致？对齐是否整齐？
3. **颜色使用** — 色彩是否传达正确语义（主操作/危险操作/禁用）？
4. **组件规范** — 同类组件是否统一（按钮大小、输入框样式）？
5. **点击目标** — 可点击元素热区是否足够大（最小 32px）？

## 输出格式

```
【页面分析】页面名称

── UX 问题 ──

❌ 问题：[描述]
   影响：[对用户完成任务的阻碍]
   改进：[具体怎么改]
   原则：[依据哪条原则]

── UI 问题 ──

❌ 问题：[描述]
   影响：[视觉/体验影响]
   改进：[具体怎么改]

── 优先级 ──
P0 阻断任务：
P1 增加摩擦：
P2 体验欠佳：
```

## 使用方式

- 直接贴截图：全面扫描所有问题
- 贴截图 + 说明重点：`/页面分析 重点看卡片操作区` — 聚焦分析指定区域

## 准则维护原则

- **追加新准则/规范时，必须以行业标准和主流做法为依据**（如 Material Design、Ant Design、WCAG、Nielsen Norman Group、Apple HIG 等权威来源），不可仅凭个案经验泛化为通用规则。每条新准则须标注来源，便于溯源和验证
