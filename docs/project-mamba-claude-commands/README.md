# project-mamba .claude commands 原始档案

这里完整保存 `E:\work\project-mamba\.claude\commands` 的原始 md 文件。

## 放在这里的目的
1. 保留你原始方法论和角色设定的出处
2. 方便回看某条规则最初是怎么表达的
3. 作为 `rules/` 和 `skills/` 抽取时的证据来源之一
4. 避免当前协议重构后丢失原始上下文

## 为什么不直接放进当前维护层
因为这些文件里混合了三种内容：
- 长期默认约束
- 工作流步骤
- 角色提示词

其中只有稳定的默认约束才适合进入 `rules/`，稳定的任务协议才适合进入 `skills/`。
其余内容不应直接原样升格为现行维护正文。

## 和现行维护层的关系
- 原始 md：来源档案
- `rules/`：环境级默认约束
- `skills/`：任务执行协议与回写目标
- 真实项目：项目内最终落地实现

## 关于你原始 md 里的“角色设定”
例如：
- 你是一名资深交互视觉设计师
- 你是一名资深前端开发工程师

这些角色设定，本质上属于“执行角色 / 提示词角色”。
它们回答的是：
- 模型以什么身份工作
- 处理任务时优先关注什么
- 输出时采用什么角度

而当前 `rules/` 和 `skills/` 里的职责边界，属于“治理角色”与“协议角色”。
它回答的是：
- 谁负责维护现行约束
- 谁负责提炼规则
- 谁负责审查候选协议
- 谁负责执行和使用标准

两者不是冲突关系，而是不同层级：
- 原始 md 里的角色 = 执行层 / prompt 层角色
- 当前维护层里的角色 = 规则 / 协议治理层角色

## 以后怎么用
- 当你要追溯某条规则最初来源时，看这里
- 当你要维护环境级默认约束时，改 `rules/`
- 当你要维护任务协议和回写目标时，改 `skills/`
