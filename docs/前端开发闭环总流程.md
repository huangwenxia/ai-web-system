# 前端开发闭环总流程

## 目标
把 `ai-web-system` 中分散的标准、Skill、资产、工作台和同步机制，串成一条可执行的前端开发闭环，确保每次任务不只是“做完页面”，而是能留下可复用结果。

## 为什么要有闭环
如果没有闭环，常见结果是：
- 任务完成了，但没有沉淀任何资产
- 页面做出来了，但边界态没补齐
- 组件复制过去了，但没人知道是否可复用
- 审查提了问题，但没有回流到标准
- 下一次相似任务还是从头来

闭环的意义，就是把单次交付变成持续积累。

## 总流程
推荐把整个过程理解为八步：

1. 接收任务
2. 梳理业务与输入
3. 推导页面方案
4. 生成页面实现
5. 审查结构与质量
6. 抽取可复用资产
7. 回写标准与案例
8. 同步到真实项目或预览环境

---

## 第一步：接收任务
输入可能来自三类场景：
- 只有接口，没有原型
- 已有设计稿或参考页面
- 已有半成品代码，需要补全与治理

这一阶段的核心不是马上写代码，而是先判断任务类型。

至少要明确：
- 这是页面任务还是组件任务
- 这是原型推导还是实现落地
- 是否存在明确视觉参考
- 是否需要对接现有组件库
- 最终产物是方案、代码、评审，还是资产沉淀

## 第二步：梳理业务与输入
这一阶段要把“输入材料”整理成模型和人都能消费的结构。

主要包括：
- 接口字段与实体关系
- 页面目标与用户操作
- 列表、详情、表单、弹窗等页面类型
- 关键状态与异常态
- 目标技术栈与组件库限制

适合调用的能力：
- `schema-to-ui`
- `prototype`
- 工作台中的任务表单与输入面板

## 第三步：推导页面方案
如果没有现成设计，需要先产出页面结构方案。

这一阶段应输出：
- 页面骨架
- 区块划分
- 信息层级
- 数据展示方式
- 操作区布局
- 状态方案

关键要求：
- 不是只把字段堆上去
- 要根据业务重要度决定展示层级
- 要补空态、异常态、权限态、加载态
- 要优先映射到已有组件或模式

## 第四步：生成页面实现
当页面结构明确后，再进入实现层。

这一阶段的目标是：
- 基于既有组件库完成页面代码
- 保证状态表达完整
- 保证字段映射与业务语义一致
- 保证结构可维护、可拆分

适合调用的能力：
- `frontend-implementer`
- 组件资产库
- 页面模板

产物可能包括：
- Vue 页面代码
- 页面内区块组件
- 数据映射函数
- 文档注释或使用说明

## 第五步：审查结构与质量
代码生成后不能直接算完成，需要至少做一轮审查。

建议审查维度：
- 信息层级是否清晰
- 视觉节奏是否稳定
- 状态是否完整
- 组件边界是否合理
- 交互路径是否顺畅
- 文案术语是否统一

适合调用的能力：
- `page-analysis`
- `page-design`
- `ui-visual-review`
- `ux-analysis`

这一阶段的结果应该形成可回看的审查记录，而不是只留在对话里。

## 第六步：抽取可复用资产
不是所有页面都值得沉淀，但以下内容通常值得抽出来：
- 通用信息卡片
- 列表区块模式
- 详情页布局模式
- 状态组件
- 数据展示映射范式

这一阶段需要回答几个问题：
- 它是否可以跨任务复用
- 它是否依赖强业务上下文
- 它是否已经补齐主要边界态
- 它是否值得进入候选资产区

如果值得沉淀，应进入：
- `assets/components/candidates`
- `assets/pages/drafts` 或 `assets/pages/reusable`
- 对应 manifest 与评审记录

## 第七步：回写标准与案例
如果本次任务暴露出新的规律，不应只保留在产物里。

应考虑回写到：
- 标准文档
- 示例文档
- 组件映射规则
- 审查规则
- Skill 引用材料

常见回写触发条件：
- 同类页面反复出现相同结构
- 新的数据类型需要新的展示规则
- 某类状态缺失反复导致返工
- 组件拆分模式被验证有效

## 第八步：同步到项目或预览环境
最后一步是把知识库产物接到真实交付链路。

典型动作：
- 同步资产到真实项目
- 接入预览系统验证效果
- 记录同步路径、依赖和适配结论
- 标记 manifest 的同步状态

这一层主要解决“知识库不是孤岛”的问题。

---

## 闭环中的关键角色
为了方便理解，可以把几个目录看成不同角色：

- `standards/`：定义规则
- `skills/` / `commands/` / `agents/`：触发执行
- `apps/ai-front-workbench/`：承接任务流程
- `assets/`：沉淀结果
- `scripts/`：做自动化动作
- `docs/`：解释体系与治理策略
- `examples/`：提供可参考样板

## 对前端最重要的理解方式
如果你是前端人员，理解这个闭环时不要先陷入后端实现细节。

你可以先只抓住三件事：
- 输入怎么变成页面方案
- 页面方案怎么变成高质量代码
- 高质量代码怎么继续沉淀成可复用资产

先把这三段打通，再去看 manifest、同步脚本、预览接入，理解成本会低很多。

## 第一版最小闭环
当前最值得优先跑通的最小闭环是：

1. 输入接口与页面目标
2. 用 Skill 产出页面方案
3. 用组件库落成 Vue 页面
4. 做一轮页面审查
5. 抽出一个可复用组件
6. 写入资产目录与 manifest

只要这条链能稳定跑通，这套系统就已经开始产生真实价值。

## 结论
前端开发闭环的重点，不是把每个环节都做重，而是让每次任务都能稳定经过“生成、审查、沉淀、回流”四个动作。

这才是 `ai-web-system` 长期提升效率的核心机制。
