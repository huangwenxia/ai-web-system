# 文档链接与路径规范

## 目标

保证仓库内的 Markdown 链接、命令示例和路径写法一致、可执行、可迁移。

## 链接原则

### 1. 优先使用相对路径

正确：

```md
[体系总览](../00-总览/体系总览.md)
[rules README](../../rules/README.md)
```

不推荐：

```md
[体系总览](<repo-root>/docs/00-总览/体系总览.md)
```

### 2. 链接应指向仓库内真实存在的文件

如果文件已删除或路径将变化，应同步更新引用。

## 命令示例原则

### 1. 优先写成 clone 后可执行的形式

正确：

```powershell
node scripts/verify-encoding.mjs .
node scripts/check-absolute-paths.mjs .
```

### 2. 避免写本机绝对路径

不推荐：

```powershell
node <repo-root>/scripts/verify-encoding.mjs .
```

## 路径书写原则

- 目录名和文件名保持与仓库真实结构一致
- 文档中引用目录时尽量使用反引号包裹
- Windows 路径只在必须说明本机环境时出现

## 校验建议

修改 Markdown 后，建议执行：

```powershell
node scripts/check-absolute-paths.mjs .
```

## 结论

路径写法的目标不是“看起来整齐”，而是保证别人 clone 仓库后可以直接复用。
