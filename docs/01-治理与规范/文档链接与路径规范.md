# 文档链接与路径规范

## 目标
保证 `ai-web-system` 中的文档在以下场景都能正常使用：
- 其他人 clone 到任意目录
- 在 GitHub 网页中直接阅读
- 在本地编辑器中跨文件跳转
- 在 macOS、Linux、Windows 上保持一致

这份规范主要解决一个问题：不要把你本机的目录结构写进仓库正文。

## 核心规则
### 1. 禁止写本机绝对路径作为 Markdown 链接
不允许这样写：

```md
[体系总览](<repo-root>/docs/体系总览.md)
```

原因：
- 只有你的电脑有这个路径
- 别人 clone 后链接会失效
- GitHub 页面无法正确解析

正确写法：

```md
[体系总览](../00-总览/体系总览.md)
```

### 2. 仓库内跳转一律使用相对路径
推荐规则：
- 同目录文件：`./文件名.md`
- 上一级目录：`../`
- 跨目录引用：按仓库结构写相对路径

示例：

```md
[docs/00-总览/体系总览.md](../00-总览/体系总览.md)
[assets/README.md](../assets/README.md)
[apps/ai-front-workbench/README.md](../apps/ai-front-workbench/README.md)
```

### 3. 命令示例优先写成 clone 后可执行的形式
不推荐：

```powershell
node <repo-root>/scripts/verify-encoding.mjs <repo-root>
```

推荐：

```powershell
node scripts/verify-encoding.mjs .
```

或者：

```powershell
cd apps/ai-front-workbench
pnpm run check
```

原则是：命令应默认从仓库根目录或当前文档描述的目录可执行。

### 4. 正文描述也尽量避免写机器专属路径
不推荐：
- `<repo-root> 是你的知识库目录`
- `这些脚本默认操作 <repo-root>/assets`

推荐：
- `ai-web-system 是你的知识库目录`
- `这些脚本默认操作 assets/`

如果确实要说明 Windows 示例路径，应明确标注“示例路径”，不要把它写成仓库事实。

## 推荐写法对照
### 文档链接
错误：
```md
[Skill协议规范](<repo-root>/docs/Skill协议规范.md)
```

正确：
```md
[Skill协议规范](./Skill协议规范.md)
```

### 跨目录链接
错误：
```md
[workbench README](<repo-root>/apps/ai-front-workbench/README.md)
```

正确：
```md
[workbench README](../apps/ai-front-workbench/README.md)
```

### Git 命令
错误：
```powershell
git -C <repo-root> status
```

正确：
```powershell
git status
```

### 脚本命令
错误：
```powershell
powershell -Command "[Console]::OutputEncoding = [System.Text.Encoding]::UTF8; & '<repo-root>/scripts/同步全局终端入口.ps1'"
```

正确：
```powershell
powershell -Command "[Console]::OutputEncoding = [System.Text.Encoding]::UTF8; & '.\\scripts\\同步全局终端入口.ps1'"
```

## 适用范围
这份规则适用于：
- `README.md`
- `docs/*.md`
- `examples/*.md`
- `scripts/**/*.md`
- `apps/**/README.md`
- 其他仓库内说明文档

## 提交前检查建议
修改文档后，至少做两件事：

```powershell
node scripts/verify-encoding.mjs .
rg -n "E:\\work\\ai-web-system" . -g "*.md"
```

如果第二条还有结果，说明文档里仍然残留本机路径。

## 结论
文档应该描述“仓库结构”，不是“你的电脑路径”。

只要记住一条就够了：
- 仓库内链接用相对路径
- 仓库内命令用可移植写法
