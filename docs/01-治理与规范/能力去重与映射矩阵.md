# 能力去重与映射矩阵

## 目标

避免把同一类内容同时写进多个目录，导致职责重叠和维护混乱。

## 映射矩阵

| 目录 | 回答的问题 | 应该写什么 | 不该写什么 |
| --- | --- | --- | --- |
| `standards/` | 什么算对 | 长期规则、标准正文 | 单次任务结论、操作步骤 |
| `rules/` | 哪些约束默认生效 | 项目级行为约束 | 详细 workflow、技能协议 |
| `.cursor/` / `.trae/` | 如何投影到终端 | 规则投影、模板 | 新的标准正文 |
| `skills/` | 任务如何执行 | 执行步骤、输入输出约束、显式调用约定 | 标准正文、项目规则 |
| `agents/` | 谁负责什么 | 角色边界、协作方式 | 技能执行细节 |
| `docs/` | 体系如何解释 | 总览、治理说明、维护规范 | 长期标准正文 |
| `examples/` | 有哪些可参考写法 | 示例任务、示例调用 | 正式规则 |
| `scripts/` | 哪些动作可工具化 | 校验、同步、辅助脚本 | 规则正文 |

## 维护顺序

1. 先判断内容属于哪一层
2. 先改维护源，再改投影层
3. 如果是单次任务结论，优先写到 `docs/` 或 `examples/`，不要直接升级为标准

## 结论

去重的核心不是少写文档，而是让每个目录只承担一种职责。
