# 分层巡检结果 - 2026-04

## 巡检目标
检查 `rules / commands / skills / agents / docs` 之间是否仍存在：
- 职责重叠
- 口径过期
- 缺位或错位
- 会误导后续维护的说明文档

本次巡检不处理：
- `docs/原始准则来源/`
- `docs/90-归档/`

原因：
- 前者是来源档案，不应按现行体系强改
- 后者是探索归档，保留历史上下文更重要

## 本次确认的主结论
当前主分层已经基本稳定：
- `standards/`：规则来源
- `.cursor/rules/`：环境级默认约束与任务路由
- `commands/`：显式任务入口
- `skills/`：执行协议
- `agents/`：角色边界与专项执行责任
- `docs/`：架构说明与治理文档

也就是说，当前最主要的问题已经不是“缺目录”，而是“少数说明文档还在沿用旧口径”。

## 本次发现的主要问题
### 1. Skill 仍被部分文档写成“入口模板”
这是当前最容易误导维护的旧表述。

实际应理解为：
- `commands/` 是入口
- `skills/` 是执行协议

### 2. Agent README 存在旧边界描述
`agents/README.md` 之前仍写着：
- Skill 提供入口模板

这会让后续维护再次把 `agent`、`command`、`skill` 混写。

### 3. 部分总览文档仍沿用旧“四层入口层”口径
问题不在“四层”本身，而在第二层内部没有拆开：
- `commands`
- `skills`
- `agents`

因此本次统一改为“协议层”口径，并在层内再拆三种职责。

### 4. 能力矩阵里有少量历史状态未更新
例如：
- `prototype-skill` 仍被描述为“内容略短”
- `schema-to-ui-skill` 仍被描述为“待继续增强输入契约”

这些判断在当前版本已经过期。

## 本次已完成的修正
已更新：
- `README.md`
- `skills/README.md`
- `agents/README.md`
- `docs/00-总览/四层关系.md`
- `docs/00-总览/体系总览.md`
- `docs/01-治理与规范/Skill协议规范.md`
- `docs/01-治理与规范/Agent适用边界清单.md`
- `docs/01-治理与规范/能力去重与映射矩阵.md`

修正方向统一为：
- `commands` 负责入口
- `skills` 负责执行协议
- `agents` 负责角色边界
- `rules` 负责环境与路由

## 当前仍然保留但不处理的点
### 1. `docs/原始准则来源/`
保持不动。

它的职责是保留最初意图和来源，不要求完全跟现行口径一致。

### 2. `docs/90-归档/`
保持不动。

归档文档允许保留探索时的旧表述，不作为现行主维护依据。

### 3. `agents/组件文档Agent.md`
暂不删除。

它目前更像低频专项角色，而不是主工作流角色。
当前结论是：
- 可以保留
- 但不应再扩写成主链路中的核心 agent

## 当前建议的主维护顺序
1. `standards/`
2. `.cursor/rules/`
3. `docs/00-总览` 与 `docs/01-治理与规范`
4. `commands/`
5. `skills/`
6. `agents/`

## 后续建议
下一轮更值得做的不是继续补说明文档，而是：
1. 为 `commands/` 和 `skills/` 建一份“一对一对应关系表”
2. 为 `agents/` 建一份“主链路角色 / 低频专项角色 / 保留待定角色”清单
3. 视使用频率决定是否真的需要补 `prototype agent` 或 `ux agent`

## 结论
`ai-web-system` 当前不需要再大删大改。

更合理的做法是：
- 维持现有主分层
- 持续修正过期口径
- 让 `rule / command / skill / agent` 的边界越来越清楚

这比继续增加目录或继续堆新提示词更重要。
