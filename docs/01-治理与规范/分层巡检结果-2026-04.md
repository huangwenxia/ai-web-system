# 分层巡检结果 - 2026-04

## 巡检目标

检查 `rules / skills / agents / docs` 之间是否仍存在：

- 职责重叠
- 口径过期
- 缺位或错位
- 会误导后续维护的说明文档

本次巡检不处理：

- `docs/原始准则来源/`
- `docs/90-归档/`

原因：

- 前者是来源档案，不应按现行体系强改
- 后者是探索归档，保留历史上下文更重要

## 本次确认的主结论

当前主分层已经稳定为：

- `standards/`：规则来源
- `.cursor/rules/`、`.trae/rules/`：环境级默认约束与规则投影
- `skills/`：任务执行协议，同时承担显式调用约定
- `agents/`：角色边界与专项协作责任
- `docs/`：架构说明与治理文档

也就是说，当前最主要的问题已经不是“缺目录”，而是“少数说明文档还在沿用旧 commands 口径”。

## 本次发现的主要问题

### 1. 部分文档仍把 `commands/` 当成独立入口层

这会让后续维护继续假设“入口和协议必须拆成两层”，与当前仓库事实冲突。

### 2. 外部项目同步说明仍保留 `--target-project`

这会误导维护者继续从 `ai-web-system` 向外部项目目录注入终端 / 插件资产。

### 3. 终端适配说明里仍混有历史 commands 同步策略

这与当前“只维护 skills + rules，同时清理旧 commands 残留”的脚本行为不一致。

## 本次已完成的修正

已统一更新：

- `README.md`
- `CLAUDE.md`
- `skills/README.md`
- `rules/README.md`
- `scripts/README.md`
- `docs/00-总览/*`
- `docs/01-治理与规范/能力去重与映射矩阵.md`
- `docs/02-资产与同步/终端适配矩阵.md`

统一后的口径是：

- `skills` 负责执行协议，也承担显式调用约定
- `agents` 负责角色边界
- `rules` 负责环境与路由
- `commands` 已退役
- 外部项目级终端资产不再由本仓库注入

## 当前仍然保留但不处理的点

### 1. `docs/原始准则来源/`

保持不动。它的职责是保留最初意图和来源，不要求完全跟现行口径一致。

### 2. `docs/90-归档/`

保持不动。归档文档允许保留探索时的旧表述，不作为现行主维护依据。

## 当前建议的主维护顺序

1. `standards/`
2. `.cursor/rules/` 与 `.trae/rules/`
3. `docs/00-总览` 与 `docs/01-治理与规范`
4. `skills/`
5. `agents/`

## 结论

`ai-web-system` 当前不需要再做大拆大改。

更合理的做法是：

- 维持现有主分层
- 持续修正过期口径
- 让 `rule / skill / agent` 的边界越来越清晰
