# 页面诊断打分维度与输出规范 (Diagnostic Rubric)

当使用 `page-ui-elevation` 技能为用户诊断页面并输出升维方案时，必须严格执行本规范。

---

## 🚨 前置一票否决门禁（Gatekeeper Audit）

在给出任何评分和方案之前，必须先经过以下两条红线检查。**只要命中任意一项，方案直接作废**：

1. ❌ **文案篡改与脑补检查**：方案是否试图擅自重写已有标题、修改占位符、增加宣传副标或添加胶囊标签？
2. ❌ **结构增删与便当盒堆叠检查**：方案是否在用户未要求的情况下，凭空塞入不存在的 Bento 卡片、灵感卡、画廊或功能模块？

只有在**完全保持现有文案、现有数据模型与既有业务结构**的前提下，才能进入以下评分与方案输出流程。

---

## 一、 五维诊断评估模型（满分 100 分，各 20 分）

1. **表面层级与视觉舒适度 (Surface Elevation & Comfort)**：
   - 评估暗色模式与浅色模式下的表面层级（Surface Levels）。
   - 是否存在刺眼的纯白大字、死黑塑料感或生硬的高反差？是否具备 Linear / Apple 风格的 1px 顶部反光微边缘与自然景深？
2. **既有信息架构与留白纯净度 (IA & Respectful Whitespace)**：
   - 评估信息焦点是否清晰。在专业工作台中，是否尊重了专注留白，坚决杜绝为了“填满屏幕”而进行的视觉污染？
3. **物理按压手感与即时反馈 (Physical Ergonomics & Press)**：
   - 评估高频操作（按钮、工具图标、输入框、切换器）是否具备物理回弹感知（如 `:active` 下沉 160ms `scale(0.98)`），还是只有生硬的瞬间跳色？
4. **状态过渡与转场连续性 (State Transitions & FLIP)**：
   - 评估状态切换（输入聚焦、加载转真实画面、列表换序、菜单展开）是否具备单次平滑 Reveal / FLIP，是否杜绝了多余的循环眩光与晃动？
5. **架构纯净与工程无损落地 (Clean Implementation & Accessibility)**：
   - 方案是否优先基于纯 CSS 与宿主原生能力实现，零额外无用依赖，零 DOM 污染，且严格兼容 `prefers-reduced-motion`。

---

## 二、 诊断与升维方案输出标准模版

针对用户页面，严禁输出通用营销八股文，必须严格针对**画面中真实存在的控件**输出：

```markdown
# 页面 UI/UX 体验升维诊断与重构方案

## 1. 场景定位与手感体检
* **页面类型判定**：[专业生产力工作台 / 极简检索中枢 / 商业营销官网]
* **文案与结构保护声明**：严格保持既有文案与业务结构不变，不新增多余内容卡片。
* **综合手感评分**：[例如：72 / 100]
* **核心交互短板**：
  1. [短板 1：例如按钮缺乏物理按压反馈，点击生硬]
  2. [短板 2：例如输入框 focus 切换时边框跳跃突兀，暗色下缺乏表面微反光]
  3. [短板 3：例如状态交接时缺少单次平滑 Reveal]

---

## 2. 既有控件原地升维清单 (In-Place Component Elevation)

### 控件一：[例如：主操作输入框 / 创作舱]
* **现状痛点**：...
* **原地升维方案**：
  - 聚焦与悬停过渡：...
  - 暗色表面边缘反光（Top-Light Ridge）：...
* **工程参数**：时长、缓动曲线、Token 规范。

### 控件二：[例如：底栏工具按钮与模型选择触发器]
* **现状痛点**：...
* **原地升维方案**：接入 Press 物理微缩放反馈，弹层展开微阻尼。
* **工程参数**：...

---

## 3. 核心实现代码片段 (纯净无副作用)
* 给出直接作用于既有类名或组件的纯 CSS / 原生 Vue/React 样式，不改动任何业务 DOM 结构。
```
