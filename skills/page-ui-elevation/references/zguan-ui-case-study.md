## 案例一：间距和图标必须连同容器容量一起改

### 本次实现

- `apps/zguan/src/components/HeaderBox/src/HeaderBox.vue`：操作组用 `gap-2`，局部移除 `.el-button + .el-button` 的默认左 margin，避免一份组距叠加一份组件距。
- `apps/zguan/src/assets/scss/workspace.scss`：智算新增页 `.step-footer .footer-main` 同样保留单一按钮组距，图标一侧 margin 归零，只在文字一侧保留图文间距。
- `apps/zguan/src/views/index/admin/notice/components/NoticeList/index.vue` 与 `useNoticeList.ts`：工作区版本同时约束操作组/文字不换行，并将操作列从 200 调到 240，为正常公告最多三组图标文字提供容量。
- `scripts/test-zguan-action-icons.mjs` 当前覆盖 135 个主页及内嵌区块、115 个操作按钮、27 个筛选栏；同时编译相关 SFC/SCSS，而不只检查 import。

### 抽象与取舍

间距问题经常不是“值不够漂亮”，而是**多层默认样式重复拥有同一段距离**。
补图标也不是纯装饰：图文宽度会改变一行可容纳的操作。只加 `whitespace-nowrap` 而不处理列容量，会把换行转成挤压或溢出。

这里的按钮组距 8px、底栏图文距 5px、公告列宽 240px 是此快照的局部选择，不是通用标准。
“所有主页操作补图标”是本项目本轮范围，不能迁移成所有系统的硬要求；测试也明确排除没有点击动作的值容器。

### 图标/字体的边界

`TenantTreeNodeIcon.vue` 将对象类别放前、状态提示放后，借角色分工而非多层彩色标签表达信息。
其中 15px/14px、描边 1.6 是具体实现，不证明在其他字体/屏幕下必然协调。
`apps/zguan/src/assets/scss/fonts.scss` 引入共享自托管 Inter 资源，并保留数字/等宽字体职责；只能据此确认声明和引用，不能证明中文实际渲染字体或跨平台观感。

**迁移建议**：先找 spacing owner 和 icon role，再做局部比例检查；不一律换字体、减细图标或增加状态容器。

## 案例二：共享背景迁移，让选择保持同一对象的连续性

### 本次实现

- 侧栏 hover：`WorkspaceLayout/useMenuHoverPill.ts`；树 hover：`directives/treeHoverPill.ts`。
- 当前选择迁移：`directives/selectionMotion.ts`，既支持 radio-button，也支持树当前项。
- Teleport 操作菜单：`WorkspaceLayout/useActionMenuMotion.ts`，消费现有公开标记，并校正弹层缩放后的局部坐标。

共同机制是量真实目标矩形，让**背景层**去目标位置，文本、图标、点击区保持稳定。
首次进入原地出现；后续迁移；hover 到当前项时避免和选中底色重复叠加。
树滚动、筛选、懒加载、尺寸变化时撤回失效几何；减弱动效回退原生状态。

### 抽象与反例

hover 表示“现在可以操作这里”，selected 表示“当前范围是这里”，focus 表示“键盘正在这里”。
三者不能合成一块跟鼠标跑的背景；鼠标移走仍要能辨认当前范围。
迁移的是选择关系，不是“左侧树背景飞入右侧表格”，也不是把普通字段做成胶囊。

**迁移建议**：适合重复选项及当前项，不适合让名称随鼠标移动或让背景跨不可见树节点追赶。

## 案例三：侧栏收放不再让主画布跟着每帧改宽

### 当前工作区实现

`WorkspaceLayout/index.vue`、`useSidebarCollapse.ts`、`sidebarMotion.scss` 使用侧栏占位槽和可见侧栏两层：

1. 读取正在显示的侧栏宽度与主体左边界，再取消旧动画。
2. 占位槽一次切到最终布局，主体根据前后左边界差做 translateX 接续；侧栏可见边界单独做宽度补间。
3. 展开时先恢复菜单结构，再隐藏首帧突变；收起结束后才交给 Element Plus 的 collapse 结构。
4. 菜单使用相同的纵向行高，避免横向收放时又逐项改变纵向位置；不缩放整页文字、表格或图表。
5. 隐藏分支退出键盘交互；必要时焦点交给可见顶层入口。版本号限制旧异步准备/完成事件只能提交对应操作。

`workspace.scss` 现有 token 桥补齐了 `--ui-transition-base`。这是重要根因：**变量名写对并不代表运行入口真的加载了变量**；缺失的时长不能靠继续加 CSS 类解决。

### 抽象与边界

原则是把“最终布局计算”和“可见运动”分开，不是承诺整页完全零重排。
主体先得到最终宽度，文本最终换行仍可能改变；图表是否实际减轻 resize 开销，需要真实设备测量。
本地 256/64 宽度、42px 行高及 200ms token 不应复制为其他产品标准。

**迁移建议**：表格/图表密集画布优先检查宽度动画的责任层；小型独立容器仍可能适合原生尺寸 transition，无需一律增加占位壳。

## 案例四：筛选展开不只是让“更多条件”淡入

### 当前工作区实现

共享 `apps/common/src/components/FilterBox/src/useFilterExpandMotion.ts` 配合 `FilterBox.vue` / `BtnExpand.vue`：

- 将用户目标展开态与短暂呈现态分开，保留原字段 hidden 规则、formItemProps、值、搜索/重置语义。
- 展开时实测容器高度，新增字段整组淡入，已有字段与操作组做位置补间；输入控件不缩放、不逐字段排长队。
- 收起先让退出字段淡出并 `inert`，再按原规则卸载；焦点必要时还给原展开按钮。
- 反向先取当前画面再取消，旧版本回调不能覆盖新状态；schema 替换、中途减少动效、禁用和卸载均清理。

### 抽象与风险

动作按钮组的位置变化也是操作体验的一部分。只动画新增字段，搜索/重置仍会瞬移；只动画高度，旧字段可能先跳终点再退回。
这是“高度让位 + 已有项补位 + 新内容显现”的协作，而不是统一 scale。

**迁移建议**：共享组件变化须回归原契约与使用场景，不能只在 zguan 内证明效果就认定其他 app 无影响。当前专项隔离测试支持语义保持，但不等于所有调用方都经过真实页面验收。

## 案例五：表格等待与结果应是一条时间线

### 本次实现

`components/WorkspaceTable` 保留 EasyBill 原组件，透传 attrs、slots、events 与公开 ref。
`useTableSkeleton.ts` 根据真实公开列和旧单元格几何显示骨架，骨架不进入数据、选择、统计或导出。
`useTableMotion.ts` 区分查询变化、同范围刷新和明确静默刷新，`tableReveal.ts` 只播放当前可见数据行。

关键顺序：

**新结果提交前准备 → 原表格消费数据 → 公开 doLayout 与列宽提交 → 移除骨架 → 向最近展开区交接高度 → 同帧结果显现。**

不是等骨架/遮罩退出再把已完整显示的结果拉回起点。
查询变化的当前实现从 -6px 落到零，280ms，错峰封顶 110ms，最多 12 个可见行；同范围刷新更轻，静默更新不演出。空态仅淡入。

### 迭代经验

项目记录过“正向位移扩大短表底部滚动范围”以及“改成纯透明度丢失原有确认体感”的取舍。
当前实现保留小幅逐行位移，但从上方归零，不越过原行底边。**不是把所有动效删掉，也不是隐藏滚动条掩盖问题。**

早期文档描述沿用原遮罩退出；当前骨架版本已在本适配根下禁用直属表格原生遮罩，不能把旧描述照抄成当前实现。
源码/测试确认了时序与边界，真实固定列、横向滚动、短列表滚动条与感知流畅度仍需人工确认。

**迁移建议**：先接真实完成事件与首帧，不先堆 stagger；只限制动效回调不等于修好后端请求的旧响应覆盖。

## 案例六：展开的“顺滑”包含位置、速度和嵌套责任

### 本次实现

`components/WorkspaceExpand/heightMotion.ts`、`useExpandMotion.ts`：

- 实测内容高度；同向慢内容到达时承接当前高度、速度与剩余进度，近目标缩短时间、单调落定。
- 反向开合从当前高度立即转向，不保留朝相反方向的惯性。
- ResizeObserver 与内容提交合并到同一帧任务，过滤亚像素噪声。
- 子级自身正在补间时父区随文档流，不再逐帧追一套高度动画；子级落定后父区重新固定高度，供后续慢数据接续。
- 子表首次打开才挂载，收起结束销毁；关闭中的内容不可交互，旧 finish 不得销毁已重开的内容。

`WorkspaceTabs/index.vue` 复用原生指示器和挂载策略：嵌套时父区负责高度，面板只就地显现，避免“整个面板下移 + 每行上移”抵消或叠加。

### 抽象与取舍

“都有 transition 仍然顿”可能来自每次尺寸更新从零速度重播，也可能来自父子同时驱动同一空间。
先解决责任与接续，再决定需不需要速度模型；普通静态短区段不必复制高度数学函数。
初次 220ms、噪声 0.5px 是此实现参数，不是所有组件统一阈值。

**迁移建议**：一个几何变化只设一个主责任层；子内容可以局部出现，但不要每层都完整展开一遍。

## 案例七：表单、本地增删和浮层不另造业务生命周期

- `directives/formMotion.ts`：仅显式维度/关联选择触发；分组让位，字段只计算组内位置，不把输入/校验/统计当作切换。
- `directives/tableRowsMotion.ts`、`views/index/components/motionKeys.ts`：按稳定对象身份对应本地行/分组，不向接口 payload 添加动画 key；新增显现、删除后补位、编辑原地交接。
- `workspace.scss`：实体按钮轻按压，文字/链接/禁用/loading 按钮不统一缩放；批量上传复用原文件列表过渡、真实进度和错误区收放。
- 抽屉/弹窗使用原组件的遮罩、焦点锁定、关闭确认与返回焦点；不用全页背景缩放和第二套面板入场抢主路径。

**迁移建议**：复用已有控件的状态与过渡，先看原生机制是否已能满足；不是每个动作都新增一个 wrapper。

## 案例八：成功收束必须收向真实结果，而不是“找个角落飞走”

### 本次实现与迭代

`utils/useExportHook.ts` 在真实 `Api.job.exportTask.save` 成功后，先创建本次右上角成功通知。
`components/ExportTaskMotion/index.ts` 等通知挂载，量取其真实位置，再交给 `playGenie.ts`。

项目记录过“纸面收向左侧导航，但成功卡片从右侧出现”的方向割裂；当前代码明确收向**本张成功通知图标**。
分片沿同一时间轴完成宽面→收腰→窄束吸入，通知在过程中出现，不等纸面完全消失才开始第二幕。
当前 520ms / 24 分片是强表现的本地实现，不是默认套件。

### 必须保留的语义

- 表示导出任务已创建，不表示文件已生成或浏览器下载完成。
- 校验失败、接口失败、取消不播放；请求中关闭后即使成功，也只按真实结果通知。
- 沿用 FormDialog.show 的提交、关闭和焦点机制，Promise 不等待动画，装饰异常不转成提交失败。
- 每次通知单独关联；结果不可见、通知重新排位、关闭、滚动/resize/卸载或减少动态效果时取消装饰，不重复通知。
- 视觉副本不可交互/读屏，不截图、不存储或上传表单，不替代原业务组件。

**迁移建议**：高价值低频动作可探索；普通保存、行内操作优先就地反馈。没有真实稳定落点时不采用复杂吸入，不为它新建 Dock、计数或全局任务中心。

## 跨系统应用方案

1. **静态成组**：先检查同类操作的语义图标、单一间距、列容量、当前态与命中区；沿用目标系统字体/token，不搬 zguan 色值。
2. **高频链优先**：在一个代表页打通选择→等待→结果与展开→让位，明确主运动责任；接入连续点击、慢数据、失败和空态。
3. **局部能力复用**：CSS 状态→局部 hook/指令→app 适配组件逐级选择；保留已有业务 API 和组件契约，不先建全局动效平台。
4. **强表现按需**：来源→结果收束需独立收益判断和授权，不能盖过高频动作，也不能成为普通系统迁移的阻塞项。
5. **扩散前核验**：代表链验证后再扩同类调用点，记录接入点、排除点与未验证项；不能拿“组件有动效”代替“用户路径已接上”。

### 分开判断的结论

- **信息架构**：本案例主要解决表现与接续；不证明其他系统需要重排结构，也不据源码判定所有页面 IA 已通过真实用户验收。历史中有面板分组合并，迁移时仍须单独授权，不能当作默认精修。
- **视觉/动态交付**：已有机制和隔离证据支持迁移方案，但本轮无真实渲染证据，不能宣称 zguan 整体视觉、动态手感或设备性能已验收。
- **必须修正项**：不因缺少某种动画新增阻塞；实际若出现错误当前态、焦点遗留、请求结果错配、操作裁切或成功语义误导，应先修复再验收。当前未提交共享 FilterBox 的跨调用方体验与动态边界属于待核验，不冒充已证实缺陷。
