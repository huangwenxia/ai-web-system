# 页面路径与反馈检查清单

本文件补充 `page-review-skill` 在体验审查中的路径与反馈检查项。

## 操作路径检查
- 页面主操作是否易找
- 次操作是否过多打断主任务
- 用户是否需要来回扫视、切换模块或记忆上下文
- 危险操作是否与普通操作清晰区分

## 反馈机制检查
- 提交前是否有预期说明
- 提交中是否有明确反馈
- 提交后是否能明确判断成功或失败
- 失败后是否给出恢复路径或下一步动作

## 状态检查
- Loading：是否知道系统正在做什么
- Empty：是否知道当前为什么为空、下一步能做什么
- Error：是否知道失败原因和恢复方式
- Permission：是否知道为什么不能操作
- Disabled：是否知道为什么不可用
- Selected / Active：是否知道当前选中或激活状态

## 认知负担检查
- 术语是否一致
- 字段是否站在用户视角表达
- 说明文字是否压过主信息
- 是否存在同义词混用、状态命名漂移或按钮语气不一致

## 输出提醒
- 如果问题集中在实现细节而不是审查结论，明确标记可转 `frontend-implementer`
- 如果问题本质是新增方案未定，不要假装是审查结论，应转回 feature / prototype 链路
