# 既有项目修复与优化检查清单

本文件补充 `existing-project-fix-skill` 在 A-3 修复主链中的检查项。

## 任务识别检查
- 是否确认任务属于 bug 修复、代码优化或局部体验修正
- 是否排除了“新增功能开发”或“独立审查任务”
- 是否明确了 `issue_type`

## 上下文追踪检查
- 是否找到目标页面、组件、函数、composable、状态源和接口调用
- 是否确认关键调用方、被复用方和路由入口
- 如果触达公共层，是否评估了兼容性影响

## 根因定位检查
- 是否还原了触发路径和边界条件
- 是否判断清楚异常是状态源问题、条件判断问题、依赖关系问题、副作用问题，还是纯展示问题
- 是否有足够证据支撑当前修复策略

## 修复策略检查
- 是否优先修真正根因，而不是表面补丁
- 是否把修改范围控制在最小充分
- 是否在必要时才扩大到共享逻辑层

## 实现与回归检查
- 是否完成当前问题修复
- 是否顺手检查同链路的对齐、节奏、状态和顺滑度
- 是否覆盖相关 loading / empty / error / permission / disabled 状态
- 是否说明了回归风险和最小验证范围

## 叠加能力检查
- 是否真的需要升级为独立 `page-review-skill`
- 是否需要叠加 `translate-terms-skill`

## 输出前检查
- 是否说明上下文定位结果和影响范围
- 是否说明修复策略与原因
- 是否给出最小验证建议
- 是否判断了是否值得回写
- 是否明确区分回写层级：`skills/` / `rules/` / Claude memory / 当前任务结论
- 是否检查了主 skill 或子 skill 是否需要同步升级
