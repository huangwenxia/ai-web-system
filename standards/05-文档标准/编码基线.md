# 编码基线

## 命名与结构
- 组件命名使用 PascalCase
- 组合式函数使用 `use` 前缀
- 事件命名优先使用动词或标准模型更新语义
- Props 定义优先使用 TypeScript interface

## 推荐文件结构
1. imports
2. props 与 emits
3. composables 与 stores
4. reactive state
5. computed
6. methods
7. lifecycle hooks

## 代码质量要求
- 避免 `any`
- 响应式能力使用要有明确职责
- 变量和函数命名必须表达业务语义
- 公共逻辑应抽到 composables
- 如果目标项目已经建立 Tailwind CSS体系，默认优先复用 Tailwind 工具类组织样式
- 除必要的动态背景、复杂运行时样式或框架工具类无法稳定表达的场景外，不应优先新增分离样式文件
-组件文档与实现说明中，应明确记录是否存在“必须脱离 Tailwind”的样式原因
- 同类数据展示尽量只做一次组件

## 说明
这里存长期基线，不存某个框架版本的临时写法偏好。
