# 为什么要做标准库

## 结论
这套标准库在 AI 全自动编程时代不是可有可无，反而更重要。

它的作用已经不是“方便人工写页面”，而是作为：
- 约束 AI
- 复用 AI
- 校准 AI
- 审查 AI

的基础设施。

## 为什么 AI 时代更需要它
1. AI 生成速度越快，风格漂移和结构漂移越容易被放大。
2. AI 会生成组件，但不会天然形成长期可维护的组件体系。
3. AI 会解释代码，但不会自动替你沉淀团队知识。
4. 真正稀缺的不是一次生成能力，而是稳定的判断标准。

## 标准库不是普通组件库
它不只是存代码，而是存一套可复用的 UI 决策系统：
- 审美标准
- 布局标准
- 数据映射标准
- 组件标准
- 文档标准

## 为什么不能只靠 Skill / commands
因为 Skill / commands 适合做工作流入口，不适合做规则本体。

如果规则同时存在于：
- 标准库
- command 文档
- skill 文档

就会产生规则漂移、双份维护和版本混乱。

## 正确关系
- `ai-web-standards` 是唯一主库
- Skill / commands 是薄入口
- 模型和人都从这里读取标准

## 当前最适合的推进方式
先把标准库本体做扎实，再考虑：
- skill
- commands
- agent
- 可视化产品

顺序不能反。
