# 53 Page Review Workflow

当任务属于“页面审查 / 视觉审查 / UX 审查”时，优先这样做：
- 先给出发现的问题，再给原因、影响和修改建议。
- 审查重点包括：信息层级、视觉节奏、组件边界、交互路径、状态完整性、术语统一。
- 审查不等于挑格式；优先识别结构性风险与可维护性风险。
- 如果问题属于长期高频模式，应标记为标准或案例回写候选。
- 该规则只负责触发与路由提醒，具体审查协议由对应 skill 承担。
