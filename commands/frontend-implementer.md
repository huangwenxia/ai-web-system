# frontend-implementer

用于直接触发“前端实现 / bug 修复 / 组件重构 / 文档补全”类任务。

## 适合什么时候用
- 需要把原型、设计稿、字段结构落成 Vue / TS 代码。
- 需要修复已有页面或组件的 bug。
- 需要优化组件边界、状态归属、模板结构或样式组织。
- 需要为已有组件补齐文档说明。

## 不适合什么时候用
- 还没有完成业务梳理与页面骨架设计。
- 任务本质上是 schema 到 UI 的结构推导。
- 任务本质上是 UX / UI 审查，而不是直接落代码。

## 执行前先读
- `standards/04-组件标准`
- `standards/05-文档标准`
- 必要时读取 `standards/01-视觉标准`

## 执行步骤
1. 先判断本次任务属于：实现 / bug 修复 / 重构 / 文档补全。
2. 概括当前输入前提：原型、字段、现有代码、bug 现象或约束条件。
3. 明确本次主要遵循的标准范围。
4. 输出实现结果或修改结果，并说明边界态、风险和验证方式。
5. 如果任务其实还缺页面结构方案，显式转交 `prototype` 或 `schema-to-ui`。
6. 如果实现后仍需结构、视觉或交互诊断，再转交 `page-analysis` / `ui-visual-review` / `ux-analysis`。

## 输出至少包含
1. 主任务类型与输入前提。
2. 本次使用的标准范围。
3. 实现 / 修复 / 重构 / 文档补全结果。
4. 风险与边界说明。
5. 最小验证建议。
6. 是否需要后续审查或回写。

## 交接规则
- 结构未明确 -> 转 `prototype` 或 `schema-to-ui`
- 需要进一步审查 -> 转 `page-analysis` / `ui-visual-review` / `ux-analysis`

不要在这个 command 文件里重写完整协议正文。
更完整的执行细则由同名 skill 承担。
