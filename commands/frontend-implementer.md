# frontend-implementer

用于触发“前端实现 / 代码修复 / 组件重构 / 文档补全”类任务。

## 适合什么时候用
- 需要把原型、设计稿、字段结构落成 Vue / TS 代码。
- 需要修复已有页面或组件的 bug。
- 需要优化组件边界、状态归属、模板结构或样式组织。
- 需要为已有组件补齐文档说明。

## 不适合什么时候用
- 还没有完成业务梳理与页面骨架设计。
- 任务本质上是 schema 到 UI 的结构推导。
- 任务本质上是 UX / UI 审查，而不是直接落代码。

## 调用前建议先确认
- 当前任务的主工作流是否确实是“前端实现”。
- 是否已有原型、设计稿、接口结构或现成页面作为输入。
- 是否需要先走 `prototype` 或 `schema-to-ui`。

## 执行前先读
- `standards/04-组件标准`
- `standards/05-文档标准`
- 必要时读取 `standards/01-视觉标准`

## 交给执行层时至少应输出
1. 主任务类型与输入前提。
2. 需要遵循的标准范围。
3. 本次是实现、修复、重构，还是文档补全。
4. 是否需要后续叠加审查流。

## 交接关系
- 如果发现当前任务其实还没有页面结构方案，转交 `prototype` 或 `schema-to-ui`。
- 如果实现完成后需要结构、视觉或交互审查，再交给 `page-analysis` / `ui-visual-review` / `ux-analysis`。

不要在这个 command 文件里重写完整执行协议。
执行步骤应继续由对应 skill 与 rule 承担。
