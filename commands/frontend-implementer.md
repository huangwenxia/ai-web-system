# frontend-implementer

用于直接触发“前端实现 / bug 修复 / 组件重构 / 文档补全”类任务。

## 适合什么时候用
- 需要把已确认的原型、设计稿或既有页面方案落成 Vue / TS 代码。
- 需要修复已有页面或组件的 bug。
- 需要优化组件边界、状态归属、模板结构或样式组织。
- 需要为已有组件补齐文档说明。

## 不适合什么时候用
- 还没有完成原型确认。
- 任务本质上是页面结构生成或 UI 原型设计。
- 任务本质上是独立页面审查，而不是直接落代码。

## 执行前先读
- `standards/04-组件标准`
- 必要时读取 `standards/01-视觉标准`
- 必要时读取 `standards/02-布局标准`

## 执行步骤
1. 先判断本次任务属于：实现 / bug 修复 / 重构 / 文档补全。
2. 概括当前输入前提：原型、设计稿、现有代码、bug 现象或约束条件。
3. 明确本次主要遵循的标准范围。
4. 输出实现结果或修改结果，并说明边界态、风险和验证方式。
5. 如果当前是新功能开发但还没有已确认原型，显式转回 `existing-project-feature` 或 `agione-ui-skill`。
6. 如果实现后仍需独立审查，再转交 `page-review`。

## 输出至少包含
1. 主任务类型与输入前提。
2. 本次使用的标准范围。
3. 实现 / 修复 / 重构 / 文档补全结果。
4. 风险与边界说明。
5. 最小验证建议。
6. 是否需要后续审查或回写。

## 交接规则
- 新功能开发但原型未确认 -> 转 `existing-project-feature` 或 `agione-ui-skill`
- 需要进一步独立审查 -> 转 `page-review`

不要在这个 command 文件里重写完整协议正文。
更完整的执行细则由同名 skill 承担。
