# ux-analysis

用于直接触发“信息层级 / 操作路径 / 反馈机制 / 认知负担”类 UX 分析任务。

## 适合什么时候用
- 需要分析页面或流程中的 UX 风险。
- 需要判断用户主任务是否顺畅、是否有认知负担或反馈缺失。
- 需要先输出问题清单和交互优化建议，而不是直接写代码。

## 不适合什么时候用
- 任务主要是视觉层级和视觉样式审查。
- 任务主要是页面骨架推导。
- 任务主要是 bug 修复或实现落地。

## 执行前先读
- `standards/02-布局标准`
- 必要时读取 `standards/01-视觉标准`

## 执行步骤
1. 先说明用户主任务和主要操作路径。
2. 分析当前页面或流程中的 UX 风险。
3. 给出可执行的交互优化建议。
4. 判断是否需要继续交给实现流、UI 审查流或综合页面分析流。
5. 判断哪些结论值得沉淀成 UX 规则或案例。

## 输出至少包含
1. 用户主任务与分析前提。
2. 当前页面或流程的 UX 风险。
3. 可执行优化建议。
4. 建议下一步进入哪条流。
5. 是否存在值得沉淀的高频问题模式。

## 交接规则
- 需要直接改代码 -> 转 `frontend-implementer`
- 更偏视觉层级和界面表达 -> 转 `ui-visual-review`
- 需要做综合页面结构诊断 -> 转 `page-analysis`

不要在这个 command 文件里承载完整分析协议。
更完整的执行细则由同名 skill 承担。
