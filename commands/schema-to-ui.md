# schema-to-ui

用于直接触发“接口结构 / 字段结构 -> 页面骨架与展示方式建议”类任务。

## 适合什么时候用
- 用户提供接口结构、字段结构或简要业务说明。
- 需要先把字段映射成页面结构和区块建议。
- 需要判断页面类型、中间区域布局和组件承接方式。

## 不适合什么时候用
- 已经有明确设计稿，只差前端实现。
- 任务主要是视觉设计或视觉审查。
- 任务主要是修复已有代码 bug。

## 执行前先读
- `standards/02-布局标准`
- `standards/03-数据映射标准`
- 必要时读取 `standards/04-组件标准`

## 执行步骤
1. 概括输入中的实体、字段和业务目标。
2. 先做字段分类 / 实体分类。
3. 判断页面类型、区块结构和信息优先级。
4. 给出展示方式、组件承接建议和边界状态。
5. 列出待确认项与低置信度推断。
6. 如果结构已足够清晰，指出哪些部分适合继续交给 `frontend-implementer`。

## 输出至少包含
1. 输入信息摘要与任务前提。
2. 字段分类 / 实体分类结果。
3. 页面骨架与区块建议。
4. 展示方式、组件承接建议与边界状态。
5. 待确认项与风险项。
6. 是否建议继续进入前端实现流。

## 交接规则
- 输入不足以判断业务结构 -> 先补待确认项，不强行进入实现
- 结构方案已经清楚 -> 转 `frontend-implementer`
- 如果其实更偏业务目标与任务流梳理 -> 转 `prototype`

不要在这个 command 文件里承载完整协议正文。
更完整的执行细则由同名 skill 承担。
