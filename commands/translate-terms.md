# translate-terms

用于直接触发 A-2“翻译、术语统一与 i18n”主工作流。

## 适合什么时候用
- 需要统一产品术语、组件术语、状态文案和错误提示。
- 需要做界面文案翻译或中英文对照整理。
- 需要对指定 Vue 文件或目录执行 i18n 国际化处理。
- 需要指出术语歧义、状态表达冲突、命名不一致或 locale key 缺失问题。

## 不适合什么时候用
- 任务主要是页面结构生成或页面原型确认。
- 任务主要是独立页面审查。
- 任务主要是直接实现页面代码，而不是文案和国际化处理。

## 接收参数说明
- 传入目录路径：先扫描目录下所有 `.vue` 文件，再决定处理范围。
- 传入单个文件路径：直接执行单文件文案 / i18n 处理。
- 传入术语表、文案列表、locale 文件：执行术语统一、文案整理或 key 完整性校验。

## 执行前先读
- `standards/03-数据映射标准`
- 如果涉及组件文案和状态，再读取 `standards/04-组件标准`

## 执行要求
1. 先明确当前任务属于：术语统一、文案优化、状态文案整理、Vue i18n 改造，还是 locale 校验。
2. 如果这次只是 A-1 / A-3 中的附加翻译需求，作为子流程执行，不单独打断主链路。
3. 输出统一术语建议、文案替换建议或 i18n 处理摘要。
4. 标出歧义项、冲突项、风险项和待确认项。
5. 如果涉及 i18n，说明复用的 key、新增的 key、修改的 locale 文件和 Vue 文件。
6. 如果发现稳定术语模式或国际化规范，再指出适合回写到哪里。

## 交接规则
- 如果任务其实属于新增开发，只是顺带包含翻译需求，转交 `existing-project-feature`。
- 如果任务其实属于 bug 修复或代码优化，只是顺带包含术语 / i18n 问题，转交 `existing-project-fix`。
- 如果问题根源是更广义的结构、视觉或体验审查，转交 `page-review`。
- 如果需要把统一后的文案真正改进代码，转交 `frontend-implementer`。
- 如果任务其实是原型阶段的字段展示方案确认，转交 `agione-ui-skill`。

不要在这个 command 文件里重写完整术语与 i18n 协议。
更完整的执行细则、扫描规则和模板由 `translate-terms-skill` 承担。
