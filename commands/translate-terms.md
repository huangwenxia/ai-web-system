# translate-terms

用于直接触发“术语统一 / 文案翻译 / 状态表达整理”类任务。

## 适合什么时候用
- 需要统一产品术语、组件术语、状态文案和错误提示。
- 需要做界面文案翻译或中英文对照整理。
- 需要指出术语歧义、状态表达冲突和命名不一致问题。

## 不适合什么时候用
- 任务主要是页面结构推导。
- 任务主要是视觉审查或 UX 审查。
- 任务主要是直接实现页面代码。

## 执行前先读
- `standards/05-文档标准`
- `standards/03-数据映射标准`
- 如果涉及组件文案和状态，再读取 `standards/04-组件标准`

## 执行步骤
1. 说明当前术语场景与目标语言。
2. 给出统一术语建议或翻译结果。
3. 标出歧义项、冲突项和风险项。
4. 如果发现稳定术语模式，指出适合回写到哪里。

## 输出至少包含
1. 任务场景与目标语言。
2. 统一术语建议或翻译结果。
3. 歧义项和风险项。
4. 是否需要同步更新文档、组件状态或规则说明。
5. 是否存在值得沉淀的术语规范。

## 交接规则
- 如果术语问题影响组件状态或页面表达 -> 可转 `frontend-implementer` 或 `ui-visual-review`
- 如果只是规则和文档层统一 -> 留在文档 / 规则整理流

不要在这个 command 文件里重写完整术语协议。
更完整的执行细则由同名 skill 承担。
