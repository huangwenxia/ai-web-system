# prototype

用于直接触发“业务梳理 / 原型推导 / 页面骨架设计”类任务。

## 适合什么时候用
- 只有需求描述、接口文档或业务说明，还没有明确页面结构。
- 需要先得到页面骨架、区块职责和关键交互。
- 需要输出可继续交给视觉设计或前端实现的中间方案。

## 不适合什么时候用
- 已经有完整原型或设计稿，只差前端实现。
- 任务主要是既有页面诊断或代码修复。
- 任务主要是视觉细节设计，而不是业务与结构推导。

## 执行前先读
- `standards/00-总览/如何使用标准库.md`
- `standards/02-布局标准/页面类型模板.md`
- `standards/03-数据映射标准/字段优先级规则.md`
- 必要时读取 `standards/01-视觉标准`

## 执行步骤
1. 先概括业务目标、目标用户和主任务路径。
2. 拆出主要实体、页面区块和关键交互。
3. 明确字段类型、展示方式与信息优先级。
4. 补齐边界状态和待确认项。
5. 如果结构已经足够清晰，指出哪些部分可继续交给 `page-design` 或 `frontend-implementer`。

## 输出至少包含
1. 输入信息摘要与业务目标。
2. 页面骨架与区块职责。
3. 关键交互与边界状态。
4. 待确认项与低置信度推断。
5. 建议下一步进入哪个流：`page-design` / `schema-to-ui` / `frontend-implementer`。

## 交接规则
- 更偏字段映射与中间区域组织 -> 转 `schema-to-ui`
- 更偏视觉呈现 -> 转 `page-design`
- 结构已经明确，需要直接落代码 -> 转 `frontend-implementer`

不要在这个 command 文件里承载完整协议正文。
更完整的执行细则由同名 skill 承担。
