# ui-visual-review

用于直接触发“视觉层级 / 信息组织 / 卡片节奏 / 状态表达”类审查任务。

## 适合什么时候用
- 需要审查页面、卡片、列表或详情页的视觉质量。
- 需要指出视觉层级、布局对齐、卡片节奏、状态表达上的结构性问题。
- 需要先输出问题清单和规范做法，而不是直接先改代码。

## 不适合什么时候用
- 任务主要是业务结构推导。
- 任务主要是交互路径和认知负担分析。
- 任务主要是直接写页面代码。

## 执行前先读
- `standards/01-视觉标准`
- `standards/02-布局标准`

## 执行步骤
1. 先识别页面中最突出的视觉问题。
2. 说明每个问题的影响和用户感知后果。
3. 给出对应的规范做法与优化方向。
4. 判断哪些问题应继续交给实现流修复。
5. 判断哪些问题属于高频模式，可能值得回写。

## 输出至少包含
1. 页面或组件的主要视觉问题摘要。
2. 每个问题的影响说明。
3. 对应规范做法。
4. 建议下一步是否进入实现流。
5. 是否存在值得沉淀的审查模式。

## 交接规则
- 需要直接改代码 -> 转 `frontend-implementer`
- 更偏交互路径与认知负担 -> 转 `ux-analysis`
- 更偏综合结构问题 -> 可转 `page-analysis`

不要在这个 command 文件里承载完整审查协议。
更完整的执行细则由同名 skill 承担。
