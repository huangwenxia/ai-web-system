# page-analysis

用于触发“既有页面结构诊断”类任务。

## 适合什么时候用
- 用户想知道页面为什么乱。
- 需要对既有页面做信息架构、视觉层级、交互路径、组件结构的综合诊断。
- 需要输出问题清单与优化建议，而不是直接先写代码。

## 不适合什么时候用
- 任务主要是直接修 bug 或改代码。
- 任务主要是视觉规范输出。
- 任务还停留在原型推导阶段。

## 调用前建议先确认
- 当前主工作流是否确实是“分析 / 审查”，而不是实现。
- 输入是否包含页面描述、截图、代码片段或可观察问题。

## 执行前先读
- `standards/01-视觉标准`
- `standards/02-布局标准`
- 必要时读取 `standards/04-组件标准`

## 交给执行层时至少应输出
1. 页面主任务与问题摘要。
2. 主要诊断维度。
3. 是否需要后续交给实现流修正。
4. 是否可能形成稳定审查口径。

## 交接关系
- 如果分析后需要直接落地改代码，再交给 `frontend-implementer`。
- 如果问题更偏视觉或 UX，可再细分到 `ui-visual-review` 或 `ux-analysis`。

不要在这个 command 文件里承载完整审查协议。
完整分析步骤应继续由 skill 与 rule 承担。
