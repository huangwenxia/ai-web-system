# page-analysis

用于直接触发“既有页面结构诊断”类任务。

## 适合什么时候用
- 用户想知道页面为什么乱。
- 需要对既有页面做信息架构、视觉层级、交互路径、组件结构的综合诊断。
- 需要先输出问题清单与优化建议，而不是直接先写代码。

## 不适合什么时候用
- 任务主要是直接修 bug 或改代码。
- 任务主要是视觉规范输出。
- 任务还停留在原型推导阶段。

## 执行前先读
- `standards/01-视觉标准`
- `standards/02-布局标准`
- 必要时读取 `standards/04-组件标准`

## 执行步骤
1. 先明确页面主任务和用户路径。
2. 分析信息架构问题。
3. 分析视觉层级问题。
4. 分析交互路径问题。
5. 分析组件结构问题。
6. 给出可执行的优化建议。
7. 判断后续是否需要转给实现流、UI 审查流或 UX 审查流。

## 输出至少包含
1. 页面主任务与问题摘要。
2. 信息架构问题。
3. 视觉层级问题。
4. 交互路径问题。
5. 组件结构问题与建议。
6. 建议下一步是实现、UI 审查还是 UX 审查。
7. 是否存在值得沉淀的高频问题模式。

## 交接规则
- 需要直接改代码 -> 转 `frontend-implementer`
- 更偏视觉表达质量 -> 转 `ui-visual-review`
- 更偏认知负担和用户路径 -> 转 `ux-analysis`

不要在这个 command 文件里承载完整审查协议。
更完整的分析细则由同名 skill 承担。
