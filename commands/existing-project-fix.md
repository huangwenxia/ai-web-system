# existing-project-fix

用于直接触发 A-3“既有项目 bug 修复 / 代码优化 / 局部体验修正”主工作流。

## 适合什么时候用
- 需要修复已有页面、组件、公共函数或状态链路的问题。
- 需要做代码优化、职责收敛、局部体验修正。
- 需要先定位上下文来源和影响范围，再做最小充分修改。

## 不适合什么时候用
- 任务主要是新增页面、模块或组件开发。
- 任务主要是独立页面审查、视觉审查或 UX 审查。
- 任务主要是纯翻译、术语统一或 i18n 改造。

## 执行前先读
- `rules/00-global-task-scope.mdc`
- `rules/20-bugfix-and-optimization.mdc`
- `standards/04-组件标准`
- 必要时读取 `standards/01-视觉标准`
- 必要时读取 `standards/02-布局标准`

## 执行要求
1. 先明确问题现象、目标范围和预期行为。
2. 修改前必须先定位触发路径、状态来源、调用链和复用范围。
3. 优先修真正根因，不打表面补丁。
4. 修复后顺手检查相关链路的细节一致性、状态完整性和回归风险。
5. 最终输出上下文定位、修复策略、修复结果和最小验证建议。

## 交接规则
- 发现任务其实是新增开发 -> 转 `existing-project-feature`
- 发现任务已经变成独立产品级审查 -> 转 `product-review`
- 发现问题主要是术语或 i18n -> 转 `translate-terms`

不要在这个 command 文件里重写完整主 workflow 协议。
更完整的执行细则由 `existing-project-fix-skill` 承担。
