# 模型部署就绪性与准入归因设计

- 文档状态：基于当前后端实现重新梳理，待评审
- 最后核验：2026-08-17
- 适用系统：`metis-hashrate`、`metis-xcloud`
- Hashrate 核验基线：`hashrate-dev-xia@ad6c7d150268c26a8668a7f964e635bc5ad95e0e`
- XCloud 核验基线：`xcloud-dev-xia@cf155c7797eff4c371dd589f0350e1209f048c9d`
- 配套文档：[云账号检测阶段与统一归因架构设计](./云账号检测阶段与统一归因架构设计.md)

## 1. 结论先行

当前部署前预检已经具备统一入口、固定检测分组、总体状态聚合和部署准入控制，但**还没有形成与云账号接入管理同等完整的统一归因与操作说明能力**。

当前已实现：

- 统一接口：`POST /cloudInferenceJob/deployment-precheck`；
- 四个固定检测分组：账号与凭证、产品与授权、模型与依赖、资源与配额；
- 总体状态：`PASSED / BLOCKED / UNVERIFIED`；
- 确定性失败禁止部署；
- 只有技术原因导致的 `UNVERIFIED`，才允许用户通过 `acceptUnverifiedRisk=true` 明确确认风险后继续；
- 正式 `confirmDeploy` 会重新执行同一套预检，不信任前端保存的旧结果。

当前缺失：

- 单项结果只有 `category / status / code / message`；
- 没有 `classificationStatus`，无法区分“已精确归因”和“只知道失败但未归因”；
- 没有 `reasonCode / reasonParams / sanitizedDetail`，无法表达具体归因证据；
- 没有结构化 `action`，前端不知道应该让用户改凭证、换规格、重试还是联系管理员；
- 没有明确的 `retryable`，前端只能根据粗粒度错误码自行猜测；
- 多种无关技术失败被压缩成 `TECHNICAL_UNVERIFIED`；
- `ACCOUNT_CREDENTIAL` 没有复用 XCloud 已有的凭证归因结果，而是在 Hashrate 内再次做粗粒度判断。

目标不是把云账号枚举整体复制到 Hashrate，也不是让前端建立错误码到操作说明的本地映射。目标是：

> Hashrate 继续拥有部署准入与总体状态；XCloud 继续拥有云账号身份凭证的权威归因；各领域返回同一形态的“结果、原因、证据、重试语义和处理动作”，由 Hashrate 聚合后直接交给前端展示。

## 2. 文档范围

本文只处理“用户已经选定部署方案，点击发起部署前”的就绪性检查、归因和准入决策，包括：

- 云账号是否属于当前租户、凭证是否可用；
- 目标云产品是否允许访问；
- 模型、框架版本、地域、规格和模型来源配置是否完整；
- License、目标规格和实时库存是否满足部署要求；
- 技术异常、能力未实现或云商暂时不可用时，是否允许风险继续；
- 后端如何向前端返回明确原因和下一步操作。

本文不处理：

- 云账号新增、编辑和账号列表本身的交互设计；
- 创建任务后的容器启动、模型解包、健康检查等异步运行错误；
- 通过一次预检消除预检与真实创建之间的库存、配额或权限竞态；
- 由前端编排多个后端接口或自行推导部署准入结果。

## 3. 当前后端真实实现

### 3.1 接口与调用链

当前部署前预检入口：

```http
POST /cloudInferenceJob/deployment-precheck
权限：cloudInferenceJob_add
```

当前调用链：

```text
CloudInferenceJobController.deploymentPrecheck
→ CloudInferenceJobService.precheckDeployment
→ CloudInferenceJobPrecheckService.precheck
→ 聚合四个固定检测项
→ 返回 CloudInferenceJobPrecheckVo
```

正式发起部署时：

```text
POST /cloudInferenceJob/confirmDeploy
→ 校验推荐方案
→ 再次执行 CloudInferenceJobPrecheckService.precheck
→ assertDeploymentAllowed
→ 通过后才进入 create
```

因此，预检接口只用于让用户提前看见当前结果；正式创建前的服务端复核才是最终准入边界。

### 3.2 当前响应契约

总体结果 `CloudInferenceJobPrecheckVo`：

```text
status
deploymentAllowed
riskContinuationAllowed
checkedAt
items[]
```

单项结果 `CloudInferenceJobPrecheckItemVo`：

```text
category
status
code
message
```

当前四个 `category`：

```text
ACCOUNT_CREDENTIAL
PRODUCT_AUTHORIZATION
MODEL_DEPENDENCIES
RESOURCE_QUOTA
```

当前可观察的稳定结果码：

```text
PASSED
ACCOUNT_NOT_READY
CREDENTIAL_INVALID
PRODUCT_UNAUTHORIZED
LICENSE_EXCEEDED
MODEL_CONFIG_MISSING
SPEC_SOLD_OUT
SPEC_NOT_FOUND
TECHNICAL_UNVERIFIED
```

### 3.3 四个检测项当前到底检查了什么

| 检测项 | 当前实际检查 | 能确定的结论 | 当前缺口 |
| --- | --- | --- | --- |
| `ACCOUNT_CREDENTIAL` | 按租户查询账号、账号存在、AK/SK 非空、账号云类型匹配；华为规格查询返回 401 时识别为凭证无效 | 账号不存在、未配置凭证、云类型不匹配或华为明确返回 401 时可阻断 | 未调用 XCloud 统一凭证检测；不能返回 XCloud 的精确原因、目标字段和更新凭证操作 |
| `PRODUCT_AUTHORIZATION` | AI Infra License；华为规格查询中除 401、429 外的 4xx 被归为产品未授权 | License 超额或华为明确 4xx 时可阻断 | License 与云产品授权混在一个分组；4xx 分类过宽；无结构化授权修复动作 |
| `MODEL_DEPENDENCIES` | 模型存在、框架版本匹配、云类型和地域匹配、模型云配置包含目标版本和规格、模型来源存在；华为公共模型要求 `publicModelId` | 平台内确定性配置缺失可阻断 | 多种缺失统一压成 `MODEL_CONFIG_MISSING`，用户不知道应修改模型、框架、地域、规格还是模型来源 |
| `RESOURCE_QUOTA` | 调用云商 `checkFlavorAvailability`；当前华为会查询真实规格列表并区分规格不存在、售罄和可用；其他未覆盖云商走默认未实时检测 | 华为规格不存在或售罄可阻断 | 分组名包含“配额”，但当前没有真实云配额检查；不支持实时检测和技术异常都压成 `TECHNICAL_UNVERIFIED` |

### 3.4 当前总体准入规则

总体状态优先级固定为：

```text
BLOCKED > UNVERIFIED > PASSED
```

| 总体状态 | `deploymentAllowed` | `riskContinuationAllowed` | 正式部署规则 |
| --- | --- | --- | --- |
| `PASSED` | `true` | `false` | 可直接部署 |
| `BLOCKED` | `false` | `false` | 禁止部署，不能通过风险确认绕过 |
| `UNVERIFIED` | `false` | `true` | 默认禁止；仅当用户明确传 `acceptUnverifiedRisk=true` 时继续 |

确定性阻断包括：

- 账号不存在、凭证缺失、账号与云类型不匹配；
- 云商明确返回凭证无效或产品未授权；
- AI Infra License 超额；
- 模型、框架版本、云配置或模型来源缺失；
- 目标规格不存在或已售罄。

`UNVERIFIED` 只应用于无法取得确定业务结论的情况，例如：

- 云商检测能力尚未实现；
- 云商请求超时、限流或服务暂时不可用；
- License 服务技术异常；
- 本地检测过程发生无法归类的技术异常。

当前实现的准入方向是正确的，但 `TECHNICAL_UNVERIFIED` 过于粗糙，尚不能支撑明确的用户操作。

## 4. 与 XCloud 统一归因能力的差距

XCloud 云账号检测项已经提供以下结构化字段：

```text
result: PASS / FAIL / ERROR / SKIPPED
classificationStatus: CLASSIFIED / UNCLASSIFIED / NOT_APPLICABLE
reasonCode
reasonMessage
reasonParams
errorCode
message
retryable
sanitizedDetail
action
  type
  label
  hint
  targetFields
checkedAt
```

XCloud 当前已存在的处理动作包括：

```text
UPDATE_CREDENTIALS
REFRESH_CONNECTIVITY_STATUS
```

两套契约当前对比：

| 能力 | XCloud 云账号检测 | Hashrate 部署前预检 |
| --- | --- | --- |
| 固定检测项 | 有 | 有 |
| 明确业务失败与技术错误分离 | `FAIL / ERROR` | 通过 `BLOCKED / UNVERIFIED` 粗粒度分离 |
| 精确归因状态 | 有 `classificationStatus` | 无 |
| 稳定业务原因 | 有 `reasonCode` | 只有粗粒度 `code` |
| 参数化证据 | 有 `reasonParams` | 无 |
| 脱敏详情 | 有 `sanitizedDetail` | 无 |
| 是否可重试 | 有 `retryable` | 无 |
| 操作类型与操作说明 | 有结构化 `action` | 无 |
| 总体准入决策 | 不负责部署准入 | 有，且应继续由 Hashrate 负责 |

所以，对“现在是否和云账号接入管理一样有统一归因及对应操作说明”的准确回答是：

> 目前只有统一检测分组和统一准入，没有完整的统一归因，也没有结构化操作说明。

## 5. 目标架构与 Owner 边界

### 5.1 Hashrate 是部署工作流 Owner

Hashrate 拥有：

- 部署前预检的前端业务接口；
- 部署上下文和四个检测分组；
- 模型、框架、地域、规格、模型来源和 License 规则；
- 各云商部署能力探针的编排；
- 总体 `PASSED / BLOCKED / UNVERIFIED` 聚合；
- 是否允许部署及风险继续策略；
- 部署域原因码和部署域处理动作。

### 5.2 XCloud 是账号身份凭证事实 Owner

XCloud 拥有：

- 云账号租户归属；
- 身份凭证的真实检测；
- 云商错误到账号原因的分类；
- 账号原因参数、脱敏详情和目标凭证字段；
- `UPDATE_CREDENTIALS`、`REFRESH_CONNECTIVITY_STATUS` 等账号域操作说明。

Hashrate 不应再根据异常文本复制一套账号凭证分类器，也不应读取或向前端返回明文凭证。

### 5.3 正确调用方向

```text
前端
→ Hashrate deployment-precheck
   → XCloud 账号身份凭证就绪查询
   → Hashrate 模型与依赖检查
   → common-service License 检查
   → Hashrate 云商部署适配器只读检查
→ Hashrate 聚合部署准入结果
→ 前端直接展示原因和操作
```

调用方向必须保持：

```text
Hashrate → XCloud 提供方 API 契约
```

XCloud 不反向调用 Hashrate，不保存部署上下文，也不替 Hashrate 决定是否允许部署。

### 5.4 账号归因复用方式

不建议直接在 Hashrate 中引用 XCloud 的实现类、异常分类器或数据表。建议由 XCloud 在 `hyperone-account-api` 提供一个无副作用的账号身份凭证就绪查询，内部复用现有账号探针、`CloudAccountReasonClassifier` 和 `CloudAccountHealthMessageResolver`。

该查询必须：

- 显式接收 `cloudAccountId + tenantId`；
- 只使用已保存账号，不接收或返回 AK/SK；
- 返回本次检测的 `PASS / FAIL / ERROR` 和完整原因、重试、操作字段；
- 不把部署预检伪装成 `MANUAL_SINGLE` 或 `SCHEDULED` 健康检测；
- 默认不改写 XCloud 健康快照，避免部署预检产生账号列表状态副作用；
- 由 Hashrate 把账号结果映射到部署项状态，但不得改写其原因和操作语义。

现有 `CloudAccountHealthService.syncStatus` 会触发健康检测及快照更新，触发来源当前只表达手动和定时场景，不宜未经扩展就直接作为部署预检查询。

## 6. 目标统一结果契约

### 6.1 总体结果继续保持部署语义

```text
stageCode: DEPLOYMENT_ADMISSION
status: PASSED / BLOCKED / UNVERIFIED
deploymentAllowed
riskContinuationAllowed
checkedAt
items[]
```

`stageCode` 用于明确本次归因发生在部署准入阶段，不进入 XCloud 的账号配置或账号健康阶段。总体字段继续由 Hashrate 生成，前端不得自行聚合。

### 6.2 单项结果补齐归因和操作

建议在兼容现有字段的前提下扩展 `CloudInferenceJobPrecheckItemVo`：

```text
checkCode                        # 部署域稳定检测项编码，初期与现有 category 同值
category                         # 兼容现有四个固定分组，迁移完成后可评审是否移除
status                           # PASSED / BLOCKED / UNVERIFIED / SKIPPED
code                             # 兼容旧前端，逐步降级为粗粒度结果码
message                          # 当前项简短结果

classificationStatus             # CLASSIFIED / UNCLASSIFIED / NOT_APPLICABLE
reasonCode                        # 确定性业务原因
reasonMessage                     # 后端按语言生成的原因文案
reasonParams                      # 结构化、脱敏原因参数
errorCode                         # 仅技术错误返回
retryable                         # 是否可以原条件重试
sanitizedDetail                   # 无法精确归因时的脱敏详情
skipReason                        # 仅 SKIPPED 返回
action
  type                            # 稳定操作类型
  label                           # 短操作名
  hint                            # 操作结果或必要说明
  target                          # 前端已登记的目标，不下发任意 URL
  targetFields                    # 可稳定定位时返回需修改字段
  params                          # 跳转所需的非敏感业务参数
checkedAt
```

统一的是“结果信封”，不是所有领域共用一套原因枚举：

- 账号凭证原因和动作由 XCloud 定义；
- License、模型配置、产品授权、规格和容量原因由 Hashrate 定义；
- 前端只识别稳定操作类型和目标，不维护原因码到中文说明的映射。

### 6.3 业务失败、技术错误和跳过必须分开

| 单项状态 | 含义 | 原因字段 | 准入影响 |
| --- | --- | --- | --- |
| `PASSED` | 已执行必要检查且通过 | 不返回业务原因 | 无阻断 |
| `BLOCKED` | 取得确定性阻断证据 | `reasonCode + reasonMessage + action` | 总体必为 `BLOCKED` |
| `UNVERIFIED` | 技术异常或能力未实现，无法形成确定结论 | `errorCode + message + retryable + action` | 无其他阻断时总体为 `UNVERIFIED` |
| `SKIPPED` | 因前项阻断而无需继续执行 | `skipReason` | 不额外改变总体状态 |

不允许：

- 把超时包装成凭证错误；
- 把 429 包装成产品未授权；
- 把“尚未实现配额检测”显示为配额通过；
- 当前项被前项阻断后仍显示技术异常；
- 让前端根据 `message` 文本猜测动作。

## 7. 部署域原因与操作目录

### 7.1 账号与凭证

账号项优先复用 XCloud 原因，不在 Hashrate 新建同义码。

| 原因或错误 | 准入 | 操作类型 | 操作说明 |
| --- | --- | --- | --- |
| XCloud 明确凭证格式、认证或账号绑定失败 | `BLOCKED` | `UPDATE_CREDENTIALS` | 进入云账号接入管理，定位 XCloud 返回的目标字段并更新凭证 |
| XCloud 没有历史健康结论，但本次查询取得明确结果 | 按本次 `PASS / FAIL` 映射 | 使用本次结果对应动作 | 历史快照不替代本次权威检测 |
| XCloud 本次查询也无法形成确定结论 | `UNVERIFIED` | `RETRY_PRECHECK` | 重新检测；技术异常不能伪造成账号无效 |
| XCloud 请求超时、DNS、TLS、限流或服务暂时不可用 | `UNVERIFIED` | `RETRY_PRECHECK` | 保持当前部署方案并重新检测；仅在允许风险继续时显示风险确认 |
| 账号不属于当前租户或账号不存在 | `BLOCKED` | `SELECT_CLOUD_ACCOUNT` | 返回部署页重新选择可用云账号 |
| 账号云类型与部署方案不一致 | `BLOCKED` | `SELECT_CLOUD_ACCOUNT` | 选择与目标云类型一致的账号 |

### 7.2 产品与授权

| 目标 `reasonCode` | 当前来源 | 操作类型 | 操作说明 |
| --- | --- | --- | --- |
| `PRODUCT_ACCESS_DENIED` | 云商返回可证明的产品访问拒绝 | `REAUTHORIZE_CLOUD_PRODUCT` | 按目标云产品补齐授权后重新检测 |
| `LICENSE_CAPACITY_EXCEEDED` | AI Infra License 明确超额 | `VIEW_LICENSE_USAGE` | 查看授权用量、释放占用或联系管理员扩容 |
| `PRODUCT_AUTHORIZATION_UNCLASSIFIED` | 明确 4xx 但证据不足以精确归因 | `CONTACT_ADMIN` | 展示脱敏云商错误码和 requestId，由管理员排查；不能猜成缺少某项权限 |
| `LICENSE_SERVICE_UNAVAILABLE` | License 服务技术异常 | `RETRY_PRECHECK` | 重新检测；按既有准入策略决定是否提供风险继续 |

### 7.3 模型与依赖

当前 `MODEL_CONFIG_MISSING` 应按真实检查点拆分：

| 目标 `reasonCode` | 操作类型 | 操作说明 |
| --- | --- | --- |
| `MODEL_NOT_FOUND` | `SELECT_MODEL` | 返回模型选择并选择仍然存在的模型 |
| `FRAMEWORK_VERSION_NOT_FOUND` | `SELECT_FRAMEWORK_VERSION` | 选择有效框架版本 |
| `FRAMEWORK_DEPLOYMENT_SCOPE_MISMATCH` | `CHANGE_DEPLOYMENT_PLAN` | 重新选择匹配云类型和地域的部署方案 |
| `MODEL_CLOUD_CONFIG_MISSING` | `CONTACT_ADMIN` | 由模型配置管理员补齐目标云、地域、框架版本和规格配置 |
| `MODEL_SOURCE_MISSING` | `CONTACT_ADMIN` | 配置目标地域可用的模型来源 |
| `PUBLIC_MODEL_ID_MISSING` | `CONTACT_ADMIN` | 为华为公共模型补齐云端模型标识 |
| `MODEL_DEPENDENCY_CHECK_ERROR` | `RETRY_PRECHECK` | 技术错误可重试；连续失败转管理员排查 |

### 7.4 资源与配额

当前真实能力只足以声明“规格与库存”，不能在未执行配额 API 时声称配额已通过。

| 目标 `reasonCode` | 当前是否有证据 | 操作类型 | 操作说明 |
| --- | --- | --- | --- |
| `SPECIFICATION_NOT_FOUND` | 华为已具备 | `SELECT_AVAILABLE_SPECIFICATION` | 选择目标地域实际支持的规格 |
| `SPECIFICATION_SOLD_OUT` | 华为已具备 | `CHANGE_REGION_OR_SPECIFICATION` | 更换地域或规格后重新检测 |
| `QUOTA_INSUFFICIENT` | 当前未实现 | `REQUEST_QUOTA` | 只有接入真实配额查询并取得明确证据后才能返回 |
| `CAPACITY_UNAVAILABLE` | 仅云商提供实时容量证据时成立 | `RETRY_OR_CHANGE_CAPACITY_SCOPE` | 重试或更换地域、可用区、规格 |
| `REALTIME_RESOURCE_CHECK_NOT_SUPPORTED` | 非华为等默认实现 | `RETRY_PRECHECK` 或 `CONTACT_ADMIN` | 明确提示本云类型尚未完成实时检查，不得显示通过 |
| `PROVIDER_RATE_LIMITED`、`PROVIDER_SERVICE_UNAVAILABLE` | 云商技术错误 | `RETRY_PRECHECK` | 原条件重试；不改写为库存或配额不足 |

## 8. 检测依赖与聚合规则

检测顺序：

```text
账号租户归属
→ XCloud 身份凭证
→ 云产品访问与授权
→ 模型与依赖
→ License、规格与实时资源
→ Hashrate 聚合总体准入
```

执行规则：

1. 账号不存在、跨租户、云类型不匹配或凭证明确定失败时，依赖账号的产品和实时资源检查返回 `SKIPPED / BLOCKED_BY_PREVIOUS_CHECK`。
2. 模型与依赖属于本地确定性检查，可以与云商检查并行，但返回顺序仍保持四个固定分组。
3. License 与云规格是不同事实；即使继续放在现有两个分组内，也必须使用不同原因码和操作。
4. 任一项 `BLOCKED`，总体为 `BLOCKED`，风险确认不能绕过。
5. 无 `BLOCKED` 但存在 `UNVERIFIED`，总体为 `UNVERIFIED`。
6. 全部必要项 `PASSED`，总体才为 `PASSED`。
7. `SKIPPED` 本身不把总体从 `BLOCKED` 改成 `UNVERIFIED`。
8. `confirmDeploy` 必须重新执行同一准入器；前端不得传预检结论或伪造 `deploymentAllowed`。

- 当总体为 `UNVERIFIED` 且 `riskContinuationAllowed=true` 时，才展示风险继续；

## 10. 分阶段改造方案

### 阶段一：补齐 Hashrate 结果信封

保持现有接口和四个分组不变，扩展单项结果：

- 增加 `classificationStatus`；
- 增加 `reasonCode / reasonMessage / reasonParams`；
- 增加 `errorCode / retryable / sanitizedDetail`；
- 增加结构化 `action`；
- 增加 `SKIPPED / skipReason`；
- 保留 `category / status / code / message` 兼容现有前端。

同时把 Hashrate 自有原因和操作集中到部署域枚举、分类器和消息解析器，不继续散落在 `CloudInferenceJobPrecheckService` 的条件分支与 i18n key 中。

### 阶段二：接入 XCloud 账号权威归因

由 XCloud 提供无副作用的身份凭证就绪查询契约，内部复用已有：

- `CloudAccountReasonClassifier`；
- `CloudAccountHealthReasonCode`；
- `CloudAccountHealthMessageResolver`；
- `CloudAccountHealthAction`。

Hashrate 只负责状态映射和总体准入，不复制账号原因枚举与分类规则。

### 阶段三：拆细 Hashrate 原因和动作

- 把 `MODEL_CONFIG_MISSING` 拆成实际检查点；
- 把 `TECHNICAL_UNVERIFIED` 拆成连接超时、读取超时、DNS、TLS、限流、服务不可用、响应异常、内部错误和能力未实现；
- 把 License 超额、产品授权、规格不存在、规格售罄分成独立原因；
- 为每个可操作原因配置稳定 `action.type`、短 `label` 和明确 `hint`。

### 阶段四：逐云商补充真实能力

优先级按部署主链路和可证明性推进：

1. 保持华为真实规格查询并收紧 4xx 分类；
2. 为其他已支持部署的云商实现真实规格检查；
3. 有官方只读 API 且能形成明确证据时，再增加配额、工作空间、服务角色和制品访问检查；
4. 无安全探针或无法消除竞态的能力，保持 `UNVERIFIED` 或交给创建后归因，不得伪造 `PASSED`。

## 11. 兼容与安全约束

- 不更改现有预检 URL 和 `cloudInferenceJob_add` 权限。
- 不让前端直接调用 XCloud 健康检测接口完成部署编排。
- 不向 Hashrate 或前端暴露 AK/SK、token、完整云商响应或异常堆栈。
- `reasonParams` 只允许白名单字段，云商 requestId 和错误码必须脱敏。
- `action.target` 只能使用前端预登记目标，禁止后端下发任意 URL。
- 动态原因和操作文案由后端按请求语言生成，前端不重复翻译。
- 未知 `reasonCode` 或 `action.type` 必须有兼容回退：展示后端文案，并提供“重新检测”或“联系管理员”，但不得默认放行。
- 预检不创建部署任务、不调用云商创建接口；正式部署仍需重新检查。

## 12. 验收条件

1. 前端一次调用即可获得四个固定分组、总体准入、具体原因和对应操作。
2. `BLOCKED`、`UNVERIFIED` 和 `SKIPPED` 的业务语义明确，不再全部落入 `TECHNICAL_UNVERIFIED`。
3. 确定性阻断无法通过 `acceptUnverifiedRisk` 绕过。
4. 只有无确定业务结论的技术异常或能力未实现允许进入风险继续策略。
5. 账号凭证原因和更新凭证操作来自 XCloud 权威归因，不在 Hashrate 重复分类。
6. License、模型配置、产品授权和资源可用性原因由 Hashrate 自有枚举维护。
7. 每个可操作的 `BLOCKED` 结果都有稳定 `action.type`、操作文案和前端目标。
8. 每个 `UNVERIFIED` 结果都明确 `errorCode`、`retryable` 和建议动作。
9. 前项阻断导致的后项未执行返回 `SKIPPED / BLOCKED_BY_PREVIOUS_CHECK`，不能显示通过或技术异常。
10. 前端不根据错误文本或粗粒度 `code` 推导原因、操作和准入。
11. 华为规格不存在与规格售罄保持不同原因和处理方向。
12. 未执行真实云配额查询时，页面不得显示“配额已通过”。
13. `confirmDeploy` 与预检接口复用同一准入器并在创建前重新检查。
14. 单测至少覆盖全通过、确定性阻断、技术异常风险继续、前项阻断后跳过和未知原因兼容。
