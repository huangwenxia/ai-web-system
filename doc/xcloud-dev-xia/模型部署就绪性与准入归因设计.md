## 1. 结论

当前后端已经实现部署环境检测和正式部署前二次复核，但当前前端 `dev` 分支没有接入检测界面，尚未形成当前分支上的端到端闭环。

后端当前具备：

- 异步创建检测任务；
- 按任务 ID 轮询检测进度；
- 四个固定检测项；
- XCloud 云账号只读就绪性检测；
- License、模型依赖和云商规格/库存检测；
- `BLOCKED / UNVERIFIED / ERROR / SKIPPED` 检测项结果；
- 正式 `confirmDeploy` 时重新检测，不信任前端缓存结果。

当前必须同时说明的限制：

- 前端预检实现曾在 `2e77502c7` 合入，随后被 `3365e2431` 完整回滚；
- 当前生成 API 没有部署预检 POST/GET；
- Infracube 已接入真实 `/service/resquota/my` 配额查询；AWS、Google、阿里、华为尚未接入真实部署配额探针；
- 对尚未支持实时配额的云商，资源项返回 `RESOURCE_QUOTA_CHECK_NOT_SUPPORTED`；
- 预检只提示当前检测事实，不控制前端是否发送创建请求；正式创建仍由后端按当时状态重新检查和执行。

本文只描述当前可由源码证明的实现。规划中的真实配额检测、结构化动作和更细技术归因单独放在第 12 节，不得提前对前端宣称已经支持。

## 2. 范围与 Owner

### 2.1 本文范围

本文处理用户已经选定推荐部署方案后、创建部署任务前的环境检测和准入，包括：

- 云账号是否属于当前租户；
- 云账号身份与凭证是否就绪；
- AI Infra License 是否允许新增实例；
- 模型、框架版本、云类型、地域、规格和模型来源配置是否匹配；
- 云商是否支持实时规格检查；
- 目标规格是否存在并有库存；
- 无法取得确定结论时是否允许确认风险继续。

本文不处理：

- 云账号新增、编辑和列表健康巡检；
- 真实云资源配额不足的确定性判断，仅在已接入配额 API/SDK 并取得明确证据时成立；
- 创建部署任务后的容器启动、模型解包和服务健康检查；
- 用一次预检消除预检与实际创建之间的库存、权限或配额竞态；
- 由前端直接调用 XCloud 或自行聚合准入结果。

### 2.2 Owner 边界

| 事实或决策 | Owner | 当前职责 |
| --- | --- | --- |
| 部署工作流与正式创建 | Hashrate | 组织检测、保存任务状态，并在正式提交时重新检查和执行创建 |
| 云账号身份与凭证 | XCloud | 通过 `checkReadiness` 返回只读就绪性和账号域归因 |
| AI Infra License | common-service | 判断新增一个实例是否超过授权额度 |
| 模型与部署配置 | Hashrate | 校验模型、框架、地域、规格和模型来源配置 |
| 云商规格与库存 | Hashrate 云商适配器 | 执行只读规格/库存探针并返回中间结果 |
| 页面状态和用户动作 | project-mamba | 展示后端结果并发起重新检测，不根据预检结果阻止用户发送创建请求 |

调用方向保持：

```text
前端 → Hashrate → XCloud / common-service / 云商只读探针
```

XCloud 不反向调用 Hashrate，不保存部署上下文，也不替 Hashrate 决定是否允许部署。

## 3. 当前接口

### 3.1 创建异步检测任务

```http
POST /cloudInferenceJob/deployment-precheck
权限：cloudInferenceJob_add
```

请求复用 `CloudInferenceJobConfirmDeployParam`。当前后端要求以下字段非空：

```text
modelId
frameworkType
cloudType
regionId
specId
frameworkVersionId
cloudAccountId
```

接口返回 `CHECKING` 任务和 `precheckId`。任务通过已有 `TaskExecutor` 异步执行，不在 POST 请求内等待全部云商检查完成。

### 3.2 查询检测任务

```http
GET /cloudInferenceJob/deployment-precheck/{precheckId}
权限：cloudInferenceJob_add
```

任务按 `tenantId + precheckId` 隔离，保存在 Redis：

```text
key: hashrate:deployment-precheck:{tenantId}:{precheckId}
TTL: 30 分钟
```

任务不存在或过期时返回 `cloudInferenceJob.precheck.task.notFound`。

### 3.3 正式创建部署

```http
POST /cloudInferenceJob/confirmDeploy
权限：cloudInferenceJob_add
```

正式部署不接收也不复用 `precheckId`。后端会：

```text
校验确认参数
→ 校验推荐方案仍然有效
→ 同步重新执行 CloudInferenceJobPrecheckService.precheck
→ assertDeploymentAllowed
→ 通过后组装 CloudInferenceJobAddParam
→ create
```

因此，异步检测结果只服务于提前展示和用户决策；正式部署前的同步复核才是最终准入边界。

## 4. 当前响应契约

### 4.1 总体任务

```text
precheckId
precheckStatus: CHECKING / COMPLETED / FAILED
startedAt
completedAt
items[]
```

字段说明：

| 字段 | 当前语义 |
| --- | --- |
| `precheckId` | 只用于查询本次短生命周期检测任务，不是部署幂等键 |
| `precheckStatus` | 异步任务状态；只表示检测中、正常完成或异常失败 |
| `startedAt` | 异步任务实际开始执行时间 |
| `completedAt` | 最终完成或失败时间 |
| `items` | 四个固定检测项，返回顺序稳定 |

### 4.2 单项结果

```text
checkCode
status: RUNNING / PASSED / BLOCKED / UNVERIFIED / ERROR / SKIPPED
reasonCode
reasonMessage
reasonParams
errorCode
actionHint
checkedAt
```

当前没有以下字段：

```text
classificationStatus
retryable
sanitizedDetail
action.type
action.target
skipReason
```

前端不得假设这些规划字段已经存在。

### 4.3 固定检测项

```text
ACCOUNT_CREDENTIAL
PRODUCT_AUTHORIZATION
MODEL_DEPENDENCIES
RESOURCE_QUOTA
```

`RESOURCE_QUOTA` 同时负责规格、库存和账户资源配额。当前只有 Infracube 能取得真实配额证据；其他云商的配额能力未接入时必须返回未验证，不得伪造通过或不足。

## 5. 状态机与聚合

### 5.1 异步任务状态

| 状态 | 含义 |
| --- | --- |
| `CHECKING` | 异步任务正在执行，前端继续轮询 |
| `COMPLETED` | 异步任务正常结束，具体结论只看四个检测项 |
| `FAILED` | 异步任务调度或执行异常；未完成项已补 `ERROR / DETECTION_INTERNAL_ERROR` |

总体状态不再聚合 `PASSED / BLOCKED / UNVERIFIED`，也不承担正式部署准入语义。

`FAILED` 不是无归因空结果。`CloudInferenceJobPrecheckTaskService.failTask` 会把仍为 `RUNNING` 的检测项转成 `ERROR`，写入 `DETECTION_INTERNAL_ERROR`、原因说明“部署环境检测任务执行异常”和联系管理员的操作说明；前端 Mock 必须使用同一后端原因文案，已完成检测项保留原结论。浏览器断网、网关无响应等没有取得后端响应的情况不属于该状态，也不进入部署预检归因目录。

### 5.2 单项状态

| 状态 | 含义 |
| --- | --- |
| `RUNNING` | 当前任务尚未完成该项 |
| `PASSED` | 已执行并通过 |
| `BLOCKED` | 有确定性问题证据，大概率导致部署失败，但预检不阻止继续创建 |
| `UNVERIFIED` | 能力未实现或已归因的云商技术异常，无法形成确定结论 |
| `ERROR` | 检测过程异常；由原因码区分云商未归因异常与 AGIOne 平台异常 |
| `SKIPPED` | 因前置项问题，本项没有执行 |

前置检查未通过时，依赖项返回 `SKIPPED` 和明确的前置失败原因；`SKIPPED` 不伪造成资源或配额结论。

### 5.3 当前 `PASSED` 可达性

当前资源项只存在以下终态：

- 规格不存在或售罄：`BLOCKED`；
- 实时检查不支持：`UNVERIFIED`；
- 云商调用技术异常：`UNVERIFIED`；
- 账号或产品前置条件未通过：`UNVERIFIED`；
- 规格、库存和已接入配额均通过：`PASSED`；
- 规格和库存通过但云商未支持真实配额：`UNVERIFIED / RESOURCE_QUOTA_CHECK_NOT_SUPPORTED`。

因此 `RESOURCE_QUOTA` 的 `PASSED` 已对 Infracube 可达；AWS、Google、阿里、华为在配额探针接入前仍只能返回未验证。

## 6. 当前执行顺序与依赖

实际执行顺序是：

```text
初始化四项 RUNNING
→ 查询当前租户下的目标云账号
→ 检查 AI Infra License
→ 检查模型与依赖
→ 检查 XCloud 账号就绪性
→ 账号通过后调用云商规格/库存探针
→ 将任务状态置为 COMPLETED
```

异步任务会在主要阶段后保存最新 `items`，供前端轮询展示进度。

依赖规则：

1. 账号不存在或查询失败时，不调用 XCloud 和云商规格探针。
2. 账号云类型不匹配或 XCloud 账号项未通过时，不调用云商规格探针。
3. 账号前置条件未通过时，仍为 `RUNNING` 的产品项转为 `SKIPPED / PRODUCT_AUTHORIZATION_PREREQUISITE_FAILED`，资源项转为 `SKIPPED / RESOURCE_CHECK_SKIPPED_ACCOUNT_NOT_READY`。
4. License 已经形成 `BLOCKED` 或 `UNVERIFIED` 时，后续前置失败不会覆盖其已有结论。
5. 模型检查是独立的本地确定性检查，即使账号阻断也会保留自身结果。
6. 产品访问明确失败时，资源项返回 `SKIPPED / RESOURCE_CHECK_SKIPPED_PRODUCT_NOT_READY`；产品请求未知失败时返回 `SKIPPED / RESOURCE_CHECK_SKIPPED_PRODUCT_REQUEST_FAILED`，均不伪造成规格或配额结论。

## 7. 四项检测的当前事实

| 检测项 | 当前真实检查 | 主要终态 |
| --- | --- | --- |
| 账号与凭证 | 租户账号存在、云类型一致、XCloud `checkReadiness` | 明确失败 `BLOCKED`；技术错误 `UNVERIFIED`；通过 `PASSED` |
| 产品与授权 | AI Infra License；云商规格接口中的产品访问结果 | 超额/拒绝/未分类 4xx 可 `BLOCKED`；服务或调用异常 `UNVERIFIED` |
| 模型与依赖 | 模型、框架版本、类型、云/地域范围、模型云配置、规格配置、模型来源、华为公共模型 ID | 配置缺失 `BLOCKED`；查询异常 `UNVERIFIED`；完整 `PASSED` |
| 资源与配额 | 云商实时规格、库存和账户配额；按云商能力返回证据 | 规格不存在/售罄或配额不足 `BLOCKED`；未支持或请求失败 `UNVERIFIED` |

具体原因码、动作说明和准入影响以配套映射清单为准。

## 8. 云商实时检测覆盖

| 云商适配器 | 当前实时检查 | 当前分类能力 |
| --- | --- | --- |
| 华为 ModelArts | 已覆盖 | 规格不存在、规格售罄、产品未授权、429/5xx/技术异常 |
| 阿里云 EAS | 已覆盖 | 规格不存在、规格售罄、凭证错误、产品未授权、未分类 4xx、限流和技术异常 |
| VirtualCloud | 已覆盖 | 调用可用性接口并返回规格/库存结果；调用异常由 Hashrate 外层转技术未验证 |
| AWS SageMaker | 未覆盖，使用默认实现 | `REALTIME_RESOURCE_CHECK_NOT_SUPPORTED` |
| Google Vertex AI | 未覆盖，使用默认实现 | `REALTIME_RESOURCE_CHECK_NOT_SUPPORTED` |
| Infracube | 已接入 `/service/resquota/my` | 可返回真实配额结果；异常按配额归因处理 |

默认实现返回 `realTimeChecked=false`。不得因为默认 `available=true` 就对外显示资源已通过。

## 9. 部署预检操作说明统一将“重新检测”放在句末；同一条说明不在开头和结尾重复出现。未归因云商错误不返回操作说明。正式部署准入

正式创建不读取前端缓存的预检结论，也不要求前端返回风险确认字段。后端重新检测后，`BLOCKED / UNVERIFIED / 云商未归因 ERROR / SKIPPED` 只作为提示证据，不阻止进入创建；AGIOne 平台异常或异步任务失败仍终止本次创建。`acceptUnverifiedRisk` 已从确认部署参数、创建参数和正式创建链移除。

正式部署重新执行检测意味着：

- 页面上的旧结果不构成服务端授权；
- 轮询完成后到正式提交之间仍可能发生状态变化；
- 前端必须正确处理正式提交时返回的最新创建错误。

## 10. 前端当前状态与接入要求

### 10.1 当前分支事实

- 推荐部署表单确认后直接调用 `confirmDeploy`；
- 没有部署环境检测组件；

- 生成 API 没有部署预检接口；

### 10.2 当前前后端组合风险

若当前前端与当前后端组合部署：

```text
前端直接 confirmDeploy
→ 后端重新检测
→ BLOCKED / UNVERIFIED / 云商未归因 ERROR / SKIPPED 作为提示证据
→ 没有 AGIOne 平台异常时继续创建
```

这是当前分支的端到端缺口，不属于文档可消除的问题。

### 10.3 前端重新接入前置条件

1. 从包含当前预检接口的目标 Swagger 源重新生成 `packages/api`，不要长期保留手写 API bridge。
2. 使用生成的 `precheckId / precheckStatus / items` 类型。
3. POST 创建任务后按 GET 轮询，任务状态为 `CHECKING / COMPLETED / FAILED`。
4. `COMPLETED` 后按四项 `PASSED / BLOCKED / UNVERIFIED / ERROR / SKIPPED` 展示结果。
5. 预检弹窗不控制前端是否发送创建请求。
6. 账号管理入口必须按 `reasonCode + status` 判断，不能把所有账号项异常都机械跳到接入管理。
7. 正式提交不携带预检结论或风险确认字段。
8. 正式提交再次失败时保留当前方案并展示后端最新原因。
9. 底部提示文案固定，不得改写，只调整显示条件：`COMPLETED` 且全部 `PASSED` 时显示“部署前检查只能证明当前已验证范围内满足准入条件，不能证明云端一定创建成功。”；存在 `BLOCKED / UNVERIFIED / 非平台前置 SKIPPED / 云商未归因 ERROR` 且不存在平台异常时，显示“为提升部署成功率，建议排查并解决问题，再重新检测。当前仍可创建部署任务，若部署失败，可前往「我的部署」详情查看原因并处理。”；`FAILED`、本地请求失败或 AGIOne 平台 `ERROR` 不显示底部提示。
10. 浏览器断网、网关无响应和未取得后端响应的轮询异常沿用平台通用请求错误，不伪造成部署归因码，也不计入后端归因案例。
11. 前端 Mock 只收录后端已登记并能返回完整原因语义的归因码；只有确实存在用户操作时才返回操作说明。`CLOUD_IDENTITY_ERROR_UNCLASSIFIED / CLOUD_PRODUCT_ERROR_UNCLASSIFIED / PROVIDER_ERROR_UNCLASSIFIED` 统一返回“系统未归因”，以安全过滤后的云商原始错误作为详情，`actionHint` 为空。不得把人为构造的未知码当成业务归因案例。当前下拉为 43 个根归因案例加 4 个组合场景，共 47 个案例；后端新增正式归因码时，前后端契约和文档必须同步更新。URL 中保存的场景值必须按当前 Mock 契约校验，已删除或未登记的旧值统一回落为 `FAILED_TASK` 并替换 URL，不得继续作为下拉当前值展示。

## 11. 安全与生命周期边界

- 检测任务只保存短生命周期结果，不创建部署任务或云资源。
- Redis key 包含租户维度，查询时使用当前登录租户。
- 检测任务不是审计事实，不应依赖其 30 分钟 TTL 做长期追踪。
- 不返回 AK、SK、Token、Authorization、Password、Private Key 等敏感信息。
- 不向前端返回完整云商请求、响应、Header 或异常堆栈。
- `reasonParams` 只允许来自账号域已处理的结构化参数；前端不得展示未确认安全的自由文本。
- `errorCode` 只用于脱敏诊断，不参与前端业务准入判断。
- 前端不得根据 `reasonMessage` 文本猜测状态或动作。

## 12. 规划能力，当前未实现

以下能力不得写入“当前已支持”：

- 真实云配额查询及 `QUOTA_INSUFFICIENT`；
- 有明确云商证据的 `CAPACITY_UNAVAILABLE`；
- `classificationStatus`；
- 通用 `retryable`；
- `sanitizedDetail`；
- 结构化 `action.type / target / params`；
- 按连接超时、读取超时、DNS、TLS 等拆分 Hashrate 云商探针技术原因；
- 独立 `skipReason` 字段；当前使用 `SKIPPED + reasonCode` 表达跳过原因。

若后续要引入结构化动作或改变 `RESOURCE_QUOTA` 的业务语义，需要按接口契约变更重新评审，不能只修改前端展示。

## 13. 验收与证据边界

### 13.1 当前源码级验收点

1. POST 返回 `precheckId + CHECKING` 和四个 `RUNNING` 项。
2. GET 只能读取当前租户的任务，过期任务返回不存在。
3. 异步执行保存阶段进度，完成后保存最终结果。
4. 账号明确失败不调用云商规格探针。
5. XCloud 技术错误返回账号 `UNVERIFIED`，不伪造成凭证失败。
6. License 阻断不会被后续产品结果覆盖。
7. 规格不存在与规格售罄返回不同原因。
8. 未支持实时配额的云商返回 `RESOURCE_QUOTA_CHECK_NOT_SUPPORTED`，不阻止继续创建；已支持的云商按真实配额证据返回通过、不足或未验证。
9. `BLOCKED / UNVERIFIED / 云商未归因 ERROR / SKIPPED` 只提示风险，不阻止正式创建。
10. AGIOne 平台 `ERROR` 或异步任务 `FAILED` 终止当次检查或创建。
11. 正式部署重新执行检测。
12. 异步任务失败时，所有未完成检测项均以 `ERROR / DETECTION_INTERNAL_ERROR` 结束，不向前端暴露无归因的 `RUNNING` 项。
