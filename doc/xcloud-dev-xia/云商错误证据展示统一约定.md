# 云商错误证据展示统一约定

本约定适用于部署预检单项结果及其前端 Mock。

## 返回字段

每个检测项始终返回以下顶层字段：

- `providerReasonCode`
- `providerReasonMessage`
- `providerRequestId`

取得云商错误证据时返回脱敏后的值；没有对应值时返回空字符串。`reasonParams.providerErrorCode`、`reasonParams.providerErrorMessage`、`reasonParams.providerRequestId` 继续保留，用于兼容和诊断。

## 最终展示文案

后端生成完整的 `reasonMessage`，前端不再拼接或单独展示 provider 字段：

```text
reasonMessage：providerReasonCode providerReasonMessage（请求 ID：providerRequestId）
```

缺少的 code、message 或 request ID 片段不显示；provider message 与系统归因文案完全相同时，不重复展示 message 文本，但保留 code 和 request ID。三项均为空时只展示系统 `reasonMessage`。

provider 字段必须由后端脱敏、去除完整 URL、压平换行并限长。网络、DNS、TLS、本地配置或程序异常在没有取得云商响应时不得伪造 provider 证据。

## 状态与 Mock

已实现并执行的探针无论是业务拒绝还是云商技术异常，单项状态均为 `BLOCKED`；`UNVERIFIED` 仅表示平台没有实现对应探针；`SKIPPED` 仅表示前置条件未满足。Mock 的 `reasonMessage` 必须直接模拟后端最终文案，所有带 provider 证据的场景同时提供 code、message 和 request ID 示例。
