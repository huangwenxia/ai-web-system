# 云账号前端常量与操作对接协议

## 1. 文档目的

本文面向用户侧云账号 V9 列表、新增/编辑预检测和单账号重新检测页面，固定前端需要维护的少量中英文常量，并约束动态原因、技术错误和处理操作的前后端职责。

关联后端架构：[云账号检测阶段与统一归因架构设计](./云账号检测阶段与统一归因架构设计.md)。

核心原则：

- 前端只翻译稳定、有限、直接参与UI结构的状态和检测项；
- 具体业务归因、技术错误和操作按钮文案由后端按请求语言返回；
- 前端根据稳定的 `actionType`绑定交互，不根据中文/英文文案判断行为；
- 未识别的后端枚举必须安全降级，不能执行猜测操作。

## 2. 列表展示状态Map

列表展示状态由两个后端字段合成：

```text
detectionActivity == RUNNING → CHECKING
否则使用 healthStatus
```

`CHECKING`是前端展示Key，不是后端 `healthStatus`值。

| 前端展示Key | 中文 | English | 后端条件 |
|---|---|---|---|
| `HEALTHY` | 健康 | Healthy | `detectionActivity != RUNNING && healthStatus == HEALTHY` |
| `ACTION_REQUIRED` | 需处理 | Action required | `detectionActivity != RUNNING && healthStatus == ACTION_REQUIRED` |
| `CHECKING` | 检测中 | Checking | `detectionActivity == RUNNING` |

建议Map：

```text
HEALTHY         → 健康 / Healthy
ACTION_REQUIRED → 需处理 / Action required
CHECKING        → 检测中 / Checking
```

## 3. 检测活动状态Map

字段：`detectionActivity`

| Value | 中文 | English | 展示规则 |
|---|---|---|---|
| `RUNNING` | 检测中 | Checking | 覆盖健康主状态 |
| `IDLE` | 空闲 | Idle | 不直接展示，继续读取 `healthStatus` |

`IDLE`只表示当前没有检测任务运行，不代表健康或需处理。

## 4. 固定检测项Map

字段：`checkCode / sourceCheckCode / lastAttemptCheckCode`

| Value | 中文 | English |
|---|---|---|
| `XCLOUD_ACCOUNT_INFORMATION` | 云账号信息 | Cloud account information |
| `CLOUD_IDENTITY_CREDENTIALS` | 云身份与凭证 | Cloud identity and credentials |
| `CLOUD_PRODUCT_ACCESS_PERMISSIONS` | 云产品访问与权限 | Cloud product access and permissions |

三个响应槽位始终按以上顺序返回。新增账号执行三项；只修改名称时后两项返回 `SKIPPED / NOT_REQUIRED`，但槽位不能消失。

## 5. 检测项结果Map

字段：`result / lastAttemptResult`

| Value | 中文 | English | 含义 |
|---|---|---|---|
| `PASS` | 检测通过 | Passed | 必要探针真实执行并通过 |
| `FAIL` | 检测未通过 | Failed | 已取得明确业务失败证据 |
| `ERROR` | 检测异常 | Check error | 网络、超时、限流或系统执行异常 |
| `SKIPPED` | 未执行 | Not run | 当前检测项未执行 |

`FAIL`和`ERROR`不能合并：前者是业务结论，后者是技术执行问题。

## 6. 未执行原因Map

字段：`skipReason / lastAttemptSkipReason`

| Value | 中文 | English |
|---|---|---|
| `WAITING_FOR_PREVIOUS_CHECK` | 等待前一项检测 | Waiting for the previous check |
| `BLOCKED_BY_PREVIOUS_CHECK` | 前一项未通过，当前项未执行 | Blocked by the previous check |
| `NOT_REQUIRED` | 本次修改无需检测 | Not required for this change |
| `NOT_IMPLEMENTED` | 当前检测能力尚未支持 | Check not supported |
| `NOT_APPLICABLE` | 当前账号不适用 | Not applicable |

## 7. 检测阶段Map

字段：`stage / sourceStageCode`

| Value | 中文 | English |
|---|---|---|
| `ACCOUNT_CONFIGURATION` | 云账号配置检测 | Cloud account configuration check |
| `ACCOUNT_HEALTH` | 云账号健康检测 | Cloud account health check |

- 新增、编辑预检测属于 `ACCOUNT_CONFIGURATION`；
- 列表手动重新检测和后端定时检测属于 `ACCOUNT_HEALTH`。

## 8. 动态原因与错误文案

前端不得为 `reasonCode`、`lastAttemptErrorCode`维护中英文Map。

后端直接返回当前请求语言下的展示文案：

| 机器字段 | 展示字段 | 前端规则 |
|---|---|---|
| `reasonCode` | `reasonMessage` | 展示 `reasonMessage`，不翻译 `reasonCode` |
| `errorCode` | `message` | 预检测/重新检测展示 `message` |
| `lastAttemptErrorCode` | `lastAttemptMessage` | 列表展示 `lastAttemptMessage` |

`messageKey / lastAttemptMessageKey`仅作为后端国际化查找键和持久化依据，不属于前端展示协议。

## 9. 操作类型与前端处理器

后端返回：

```text
actionType / action.type        机器操作码
actionLabel / action.label      后端翻译后的按钮文案
```

前端直接展示后端Label，只根据Type选择处理器。

| actionType | 业务含义 | 前端处理器 |
|---|---|---|
| `RECHECK` | 重新检测 | 调用单账号重新检测接口 |
| `CHANGE_ACCOUNT_NAME` | 修改名称 | 打开编辑账号弹窗并聚焦名称 |
| `UPDATE_CREDENTIALS` | 更新凭证 | 打开编辑账号弹窗并进入凭证编辑状态 |
| `USE_ORIGINAL_ACCOUNT_CREDENTIALS` | 使用原账号凭证 | 打开凭证编辑并展示主体不一致提示 |
| `VIEW_EXISTING_ACCOUNT` | 查看已有账号 | 导航或定位已有账号 |
| `ENABLE_CLOUD_PRODUCT` | 开通云产品 | 打开统一云商处理指南 |
| `VIEW_REQUIRED_PERMISSIONS` | 查看所需权限 | 打开统一云商处理指南 |
| `CONFIGURE_CLOUD_PRODUCT_AUTHORIZATION` | 配置产品授权 | 打开统一云商处理指南 |
| `REPAIR_CLOUD_PRODUCT_AUTHORIZATION` | 修复产品授权 | 打开统一云商处理指南 |
| `RESOLVE_CLOUD_ACCOUNT_RESTRICTION` | 处理账号限制 | 打开统一云商处理指南 |

前端实现应收敛为四类稳定处理器：

1. 编辑账号；
2. 重新检测；
3. 查看已有账号；
4. 打开统一云商处理指南。

Hashrate终端用户自行管理自己的云账号，因此不提供“联系云账号管理员”或“联系平台管理员”操作。云账号停用、受限统一使用 `RESOLVE_CLOUD_ACCOUNT_RESTRICTION`进入处理指南；检测配置、代理、TLS和平台内部错误若没有真实可执行入口，只展示后端具体错误文案，不返回操作按钮。未来只有在系统具备真实诊断页面后，才新增对应可执行 `actionType`。

新增具体 `reasonCode`只要复用已有 `actionType`，前端不需要修改。新增 `actionType`属于接口契约变更，必须经过前后端同步和未知类型降级验证。

## 10. 操作上下文

当前操作对象已经包含：

```text
type
label
targetFields
```

仍需补齐以下上下文，才能让全部操作真正可执行：

| 操作 | 缺少字段 |
|---|---|
| `VIEW_EXISTING_ACCOUNT` | `targetCloudAccountId` |
| 五类云产品处理操作 | `guideCode`，必要时包含后端白名单生成的安全控制台入口 |

前端不得根据云商、原因文案自行拼接外部控制台URL。

## 11. 凭证目标字段Map

字段：`reasonParams.credentialField / action.targetFields[]`

| Value | 中文 | English |
|---|---|---|
| `ACCESS_KEY_ID` | Access Key ID | Access Key ID |
| `ACCESS_KEY_SECRET` | Access Key Secret | Access Key Secret |
| `PROJECT_ID` | 项目ID | Project ID |
| `SERVICE_ACCOUNT` | 服务账号 | Service account |
| `CREDENTIAL_BUNDLE` | 整组凭证 | Credential set |
| `UNKNOWN` | 未知凭证字段 | Unknown credential field |

`CREDENTIAL_BUNDLE`表示需要编辑整组凭证，前端不能猜测为单独AK或SK错误。

## 12. 用户侧接口接入现状

| 场景 | 当前接口/状态 |
|---|---|
| 通用新增/编辑预检测 | `POST /cloud/account/precheck`，已返回三个检测项及操作 |
| 用户侧提交新增 | `POST /cloud/endUser`，保存前会再次检测，但成功只返回账号ID |
| 通用单账号重新检测 | `POST /cloud/account/{id}/health-check` |
| 用户侧列表 | `GET /cloud/endUser`，已返回健康状态、原因、最近尝试和操作摘要 |
| 用户侧预检测入口 | 当前用户侧Controller未单独提供，应复用统一预检测Service补入口 |
| 用户侧重新检测入口 | 当前用户侧Controller未单独提供，应复用统一健康Service补入口 |

用户侧补入口时只负责租户、账号归属和权限校验，不得复制检测或归因逻辑。

## 13. V9列表字段清单

主状态：

```text
healthStatus
detectionActivity
```

当前有效结论：

```text
reasonCode
reasonMessage
actionType
actionLabel
sourceStageCode
sourceCheckCode
```

最近一次检测尝试：

```text
lastAttemptResult
lastAttemptCheckCode
lastAttemptSkipReason
lastAttemptErrorCode
lastAttemptMessage
lastAttemptRetryable
lastAttemptActionType
lastAttemptActionLabel
lastAttemptAt
```

时间规则：如果V9显示“最近检测时间”，必须绑定 `lastAttemptAt`；`updateTime / createTime`是账号配置更新时间，不能作为检测时间。

## 14. 安全降级

- 未识别 `healthStatus`：展示中性未知状态并记录前端监控，不猜测健康；
- 未识别 `actionType`：可以展示后端原因文案，但不渲染可执行按钮；
- `actionLabel`为空：不根据 `actionType`在前端临时翻译动态按钮；
- 外部URL缺少后端白名单结果：只展示指南，不允许前端拼接URL；
- 所有实际操作接口仍由后端完成权限与租户校验。
