# XCloud 云账号云产品能力检测评估

## 背景

云账号新增和编辑流程计划在原有 AK/SK 校验之外，增加以下三项检测：

1. 账号信息。
2. 云身份与凭证。
3. 云产品访问与权限。

本次结合 XCloud、Hashrate 的本地业务说明、`origin/xcloud-dev-xia` 分支代码，以及阿里云和华为云官方 API 文档，评估这项能力是否可落地，以及检测结果应该如何表达。

本次读取的目标分支版本：

```text
origin/xcloud-dev-xia
commit: 0f71270955dac9a243854b42ef062b73a361674e
```

## 核心结论

> [!success] 结论
> 云厂商官方 API 支持在添加云账号时进行云产品能力探测，但只能验证“当前凭证在指定产品、指定 Region、指定 Workspace 或 Project 下能否执行某些目标 API”，不能通过一次接口调用证明账号已经具备完整模型部署能力。

这项业务本身合理且有实际价值，可以提前发现：

- AK/SK 无效。
- 凭证绑定到了错误的云账号。
- 目标云产品接口不可访问。
- 缺少目标产品的只读权限。
- ModelArts 委托授权未配置或失效。
- 云商接口超时、限流或服务异常。

但第三项不建议继续使用宽泛的“云产品访问与权限”，推荐改为：

```text
云产品能力检测（按地域）
```

检测结果必须同时展示：

- 云产品。
- Region。
- Workspace 或 Project。
- 实际调用的检测能力。
- 已验证范围。
- 未验证范围。

## 四层能力必须分开

| 层级 | 要回答的问题 | 推荐结论 |
| --- | --- | --- |
| 凭证有效性 | AK/SK、Service Account 是否可以完成签名和认证 | 有效、无效、未验证 |
| 云身份 | 当前凭证属于哪个 Account、Domain 或 Project | 已识别、身份冲突、无法识别 |
| 产品访问能力 | 能否调用指定 Region 下的 PAI EAS 或 ModelArts API | 可访问、权限不足、未开通、未知 |
| 部署就绪能力 | 是否具备创建服务及其依赖资源、配额和授权 | 已验证、部分验证、未验证 |

不能把“某个 List API 返回成功”直接解释为“完整部署权限已开通”。

## XCloud 与 Hashrate 的职责边界

根据 [[10-projects/metis-xcloud/02-技术/2026-07-23-Metis-XCloud后端业务逻辑全景]]：

- XCloud 负责云平台、云账号、地域、资源池、规格和基础云资源接入。
- Hashrate 负责模型、框架、镜像、推理部署任务、运行状态和调用链。
- 有效云账号只是部署前置条件，不是完整部署就绪证明。

根据 [[10-projects/metis-hashrate/01-需求/管理员配置与资源接入]]，完整部署还需要：

- 业务地域授权。
- 资源池及业务授权。
- 模型来源。
- 推理框架和镜像。
- 云商部署配置。
- 可用规格、库存和配额。

因此，账号添加阶段适合做“低成本、无副作用的前置探测”，真正部署就绪检查仍应放在资源接入或确认部署前。

## 官方 API 支持情况

### 阿里云 PAI EAS

| 检测目的 | 推荐官方 API | 能够证明 | 不能证明 |
| --- | --- | --- | --- |
| 云身份与凭证 | STS `GetCallerIdentity` | 当前 AK/SK 有效，并返回调用身份 | PAI/EAS 权限 |
| PAI 工作空间访问 | AI Workspace `ListWorkspaces` | 指定 Region 下具备工作空间列表访问能力 | 具备 EAS 创建权限 |
| EAS 服务访问 | EAS `ListServices` | 指定 Region 下具备 EAS 服务查询权限 | 具备服务创建、更新和删除权限 |
| Workspace 内权限 | AI Workspace `GetPermission` | 指定 Workspace 下当前用户的权限信息 | Workspace 之外的 RAM、OSS、VPC 和配额能力 |

官方权限项至少包括：

```text
paiworkspace:ListWorkspaces
eas:ListServices
```

建议检测链：

```text
STS GetCallerIdentity
  -> ListWorkspaces(region)
  -> 选择或定位 workspaceId
  -> GetPermission(workspaceId, userId)
  -> ListServices(region, workspaceId)
```

检测结果应表达为：

```text
已验证：PAI 工作空间可查询、EAS 服务可查询。
检测范围：cn-shanghai / workspace-xxx。
未验证：创建服务、OSS、VPC、安全组、规格库存和资源配额。
```

#### 阿里云开通状态边界

官方 API 可以通过目标接口的响应或错误码识别部分“未启用、无权限、凭证错误”状态，但空列表不表示产品未开通：

- `ListWorkspaces` 返回空列表，可能只是没有可见 Workspace。
- `ListServices` 返回空列表，可能只是当前没有 EAS 服务。
- 只有云商明确返回未启用类错误码时，才能归类为“产品未开通”。
- 403 或 AccessDenied 应归类为“权限不足”，不能归类为“产品未开通”。

### 华为云 ModelArts

| 检测目的 | 推荐官方 API | 能够证明 | 不能证明 |
| --- | --- | --- | --- |
| 云身份与凭证 | IAM Domain、Project 查询 | AK/SK 有效，并可识别 Domain 和区域 Project | ModelArts 权限 |
| ModelArts 服务访问 | `ListInferServices` | 指定 Region/Project 下具备 `modelarts:service:list` | 具备创建服务权限 |
| ModelArts 委托授权 | ModelArts 授权或委托状态查询 | ModelArts 访问 OBS 等依赖服务的授权是否配置 | 资源池、规格、库存和配额可用 |
| API Key 管理 | API Key 列表或管理接口 | 具备 API Key 查询或管理权限 | 具备服务查询和创建权限 |

新版推理服务推荐使用：

```text
GET /v2/{project_id}/services
```

对应官方权限项：

```text
modelarts:service:list
```

建议检测链：

```text
IAM Domain 查询
  -> 查询 validationRegion 对应 projectId
  -> ListInferServices(projectId, region)
  -> 查询 ModelArts 委托授权状态
  -> 平台需要自动管理 API Key 时，再检测 API Key 管理权限
```

检测结果应表达为：

```text
已验证：ModelArts 推理服务列表可访问。
检测范围：cn-north-4 / project-xxx。
授权状态：已配置、未配置或未知。
未验证：创建服务、OBS、SWR、VPC、资源池、规格和配额。
```

## 真实部署依赖

### 阿里云 EAS

根据 [[10-projects/metis-hashrate/02-技术/2026-07-06-阿里云EAS模型框架与模型上架SOP]]，EAS 真实部署至少还依赖：

- 目标 Region 和 Workspace。
- EAS 公共模型 ID。
- 推理镜像和启动命令。
- OSS 路径和内部 Endpoint。
- 可部署规格及库存。
- 网络和资源配额。

因此，`ListWorkspaces + ListServices` 只能作为产品访问探测。

### 华为云 ModelArts

根据 [[10-projects/metis-hashrate/02-技术/2026-07-14-华为云新版预置模型快速部署接入建议]] 和 [[10-projects/metis-hashrate/04-变更/2026-07-17-华为云ModelArts公共模型真实部署与观测闭环复盘]]，新版 ModelArts 真实部署至少还依赖：

- 目标 Region 和 Project。
- 当前账号可见的 `asset_id`。
- 公共或专属资源池。
- 推理单元规格。
- OBS 模型目录挂载。
- SWR 推理镜像。
- 健康检查和服务配置。
- API Key 创建与绑定。
- 资源库存和配额。

因此，API Key 列表成功不能代表 ModelArts 推理服务已具备部署能力。

## 当前分支实现评估

### 1. 阿里云身份检测使用了账单 API

当前 `AliyunAccountComponent.validateAccount` 使用：

```text
QueryBillOverview
```

该接口属于账单能力，还会受到财务权限影响。可能出现：

```text
AK/SK 正确
  + 没有账单权限
  -> 被误判为账号身份检测失败
```

建议改成专门用于身份识别的：

```text
STS GetCallerIdentity
```

账单权限应作为独立业务能力，不应成为添加云账号的身份门禁。

### 2. 阿里云两个能力被串成一个检测结果

当前执行顺序为：

```text
ListWorkspaces
  -> ListServices
```

任意一个失败，整个“云产品访问与权限”都会失败。

实际可能存在：

- 有 EAS 查询权限，但没有 Workspace 列表权限。
- 有 Workspace 查询权限，但没有 EAS 服务权限。
- 可以访问一个指定 Workspace，但不能列出全部 Workspace。

建议拆成独立子项，分别保存结果和云商错误码。

### 3. 华为云检测目标偏向 API Key 管理

当前调用：

```text
GET /v2/{project_id}/services/api-keys?limit=1
```

这个接口更接近 API Key 管理权限检测，不适合作为 ModelArts 产品整体访问探针。

可能产生两类误判：

- 有服务创建权限但没有 API Key 查询权限，被判定为产品不可访问。
- 有 API Key 查询权限但缺少服务创建权限，被判定为产品能力正常。

推荐主探针改为 `ListInferServices`，API Key 管理作为独立可选子项。

### 4. 固定 Region 会产生业务误判

当前默认检测地域：

```text
阿里云：cn-shanghai
华为云：cn-north-4
```

账号表单没有 Region 上下文。如果客户只使用新加坡、贵阳或其他 Region，检测会把地域差异错误解释为：

- 产品未开通。
- 权限不足。
- 账号异常。

建议二选一：

1. 添加账号时要求选择检测 Region。
2. 使用当前租户或业务已授权 Region 逐个检测。

无论采用哪种方案，都必须在结果中返回 `regionId`。

### 5. “检测通过”的业务承诺过宽

当前第三项只有一个 `PASS`，容易被前端解释为“云产品访问与权限全部正常”。

实际只能说明：

```text
本次选择的只读探针调用成功
```

建议成功文案明确写为：

```text
目标产品可访问
```

不要写成：

```text
已具备完整权限
已具备部署权限
云产品已完全就绪
```

### 6. 技术失败与业务待处理状态混在一起

当前健康状态只有：

```text
HEALTHY
ACTION_REQUIRED
```

超时、429、云商 5xx 和网络异常最终也会进入 `ACTION_REQUIRED`，容易让用户误以为必须修改权限或账号配置。

建议增加：

```text
UNVERIFIED
```

用于表示本次因技术原因无法得出业务结论。

### 7. 当前保存策略方向基本合理

当前配置检测中：

- 身份或凭证失败会阻止保存。
- 产品访问检测失败不会阻止保存。

这一方向符合实际使用需求。产品未开通或权限未完整配置时，账号仍然可以先保存，后续由管理员处理。

需要补充的是：

- 区分业务失败和技术失败。
- 把检测范围持久化。
- 不把未验证状态显示成权限错误。

## 推荐业务契约

### UI 检测项

```text
账号信息
云身份与凭证
云产品能力检测（按地域）
```

第三项展开后显示：

```text
产品
Region
Workspace/Project
产品 API 可访问
只读权限
产品授权或委托
部署权限验证状态
未验证依赖
```

### 推荐状态

| 状态 | 含义 |
| --- | --- |
| `PASS` | 当前检测项已明确通过 |
| `FAIL` | 云商明确返回凭证、权限、授权或账号限制问题 |
| `ERROR` | 超时、限流、网络或云商服务异常 |
| `SKIPPED` | 不适用、未实现或被前置检测阻断 |

建议增加整体能力状态：

| 状态 | 含义 |
| --- | --- |
| `READY` | 当前声明范围内的检测均通过 |
| `PARTIAL` | 部分能力通过，仍有权限或授权待处理 |
| `ACTION_REQUIRED` | 云商已明确返回需要处理的业务问题 |
| `UNVERIFIED` | 技术原因导致无法判断 |

### 推荐返回范围

```json
{
  "product": "PAI_EAS",
  "regionId": "cn-shanghai",
  "workspaceId": "workspace-xxx",
  "projectId": null,
  "verifiedCapabilities": [
    "WORKSPACE_LIST",
    "EAS_SERVICE_LIST"
  ],
  "unverifiedCapabilities": [
    "CREATE_SERVICE",
    "OSS_ACCESS",
    "VPC_ACCESS",
    "QUOTA"
  ]
}
```

华为云将 `workspaceId` 替换为 `projectId`。

## 保存规则

| 场景 | 是否允许保存 | 保存后状态 |
| --- | --- | --- |
| 必填信息或账号名称不合法 | 否 | 配置信息失败 |
| AK/SK 无效 | 否 | 凭证失败 |
| 编辑时检测到云账号身份变化 | 否 | 账号绑定冲突 |
| 云产品未开通 | 是 | `ACTION_REQUIRED` |
| 缺少产品只读权限 | 是 | `ACTION_REQUIRED` |
| ModelArts 委托未配置或失效 | 是 | `ACTION_REQUIRED` |
| 超时、限流、网络错误、云商 5xx | 是 | `UNVERIFIED` |
| 当前云商未实现产品检测 | 是 | `SKIPPED` 或 `UNVERIFIED` |

确定性的凭证错误可以阻止保存；云产品、授权、权限和技术故障一般不应阻止账号先入库。

## 错误归类原则

1. 只使用云商明确返回的错误码做确定性归类。
2. 空列表不能归类为“产品未开通”。
3. 401 应优先判断凭证或 Token 问题。
4. 403、AccessDenied、Forbidden 应归类为权限不足。
5. 云商明确的 NotEnabled 或 NotActivated 才归类为产品未开通。
6. ModelArts 委托错误只在官方错误码明确对应时归类为授权未配置或失效。
7. 429、超时、连接失败和 5xx 归类为技术失败。
8. 保存脱敏后的原始云商错误码，方便后续排障和扩充映射。

## 最终建议

保留这次分支中“配置预检、健康快照、手动复检、产品失败允许保存”的整体框架。

上线前重点调整：

1. 阿里云身份检测改用 STS。
2. 华为云主探针改用推理服务列表。
3. 产品检测改为带 Region 和 Workspace/Project 的多子项能力检测。
4. 增加 `UNVERIFIED`，区分技术故障和业务待处理。
5. 所有成功结果只声明已验证的具体能力，不承诺完整部署就绪。

一句话口径：

> XCloud 可以在账号接入时验证凭证身份和目标云产品的基础可访问性，但完整部署权限必须结合目标地域、工作空间或项目、授权委托、依赖资源、规格和配额继续验证。
