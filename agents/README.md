# agents

这里存专项 Agent 的执行层设计。

## 这一层负责什么
- 定义某类专项任务由谁执行。
- 切清每个 Agent 的职责边界。
- 说明输入、输出、依赖标准和协作方式。
- 提供多 Agent 协作时的分工约束、交接条件和结果回收要求。

## 这一层不负责什么
- 不定义规则本体。
- 不成为第二主标准。
- 不替代 Skill 执行协议层。
- 不等同于真实产品内置的多 Agent 执行引擎。
- 不直接承诺某个工具已经支持并行子 Agent 或自动调度。

## 与其他层的关系
- `standards`：提供规则本体。
- `commands`：提供显式任务入口。
- `skills`：提供执行协议。
- `agents`：负责角色边界、交接约束和专项执行责任。

## 当前定位
- `agents/*.md` 主要回答“谁负责什么，不负责什么”。
- `agents/多Agent执行协议.md` 回答“主 Agent 何时拆分、如何分派、如何回收结果”。
- 如果未来某个工具真的支持原生 subagents / teams / delegation，这一层再继续映射到具体产品能力。
