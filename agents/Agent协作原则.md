# Agent 协作原则

## 基本原则
- Agent 负责执行，不负责定义规则。
- 所有 Agent 都应以 `standards` 为唯一标准来源。
- Cursor Rule 层负责环境级默认约束，Agent 不负责替代它。
- Agent 之间可以分工，但不能各自形成一套私有规范。

## 协作方式
- Rule 层负责默认挂载环境约束和任务路由。
- Skill / command 层负责把任务分配到合适入口。
- Agent 层负责按职责执行专项任务。
- 执行中发现可长期复用的结论，应回写标准库、文档、案例或规则，而不是只留在 Agent 输出里。

## 什么时候拆 Agent
只有在以下情况才值得拆专项 Agent：
- 任务边界清晰。
- 输入输出稳定。
- 可以长期重复执行。
- 与其他任务的上下文依赖较弱。

## 不要滥拆
如果只是一次性的任务步骤，或者仍高度依赖人工判断和上下文，不必马上拆成独立 Agent。

## 与 Cursor Rule 的边界
- Rule：环境级默认行为和项目级约束
- Command：用户如何触发一类任务
- Skill：任务如何执行
- Agent：谁负责执行这类任务

四者应配合，不应互相替代。
